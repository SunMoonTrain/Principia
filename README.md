# Principia

只给自己用的本地数学物理学习网站。数学和物理的主要领域切成一级一级的小节，小节之间按前置关系连成一张「知识星图」。内容由 agent 提前写成文件，网站负责显示、判题、记录进度。

一句话记住：内容是文件，网站是播放器，进度是一份能提交到 Git 的存档。

完整的设计、规矩和每一批的记录都在 [docs/plan.md](docs/plan.md)。它是写代码、写内容、审内容几个 agent 共同的唯一依据。这份 README 只是入口，两边说法不一致时以 plan.md 为准。

## 怎么用

需要 Node.js 22 以上。第一次先装依赖：

```bash
npm install
```

在 Windows 电脑上启动。它会先构建网站，再启动服务：

```bash
npm start
```

然后在浏览器里打开 <http://localhost:3141>。

- **iPad**：改运行 `npm run start:lan`。它会打印电脑的局域网地址，iPad 连同一个 Wi-Fi 打开这个地址。第一次运行时 Windows 防火墙会弹窗，只勾「专用网络」。iPad 用的时候电脑要开着。
- **网站没改过**：用 `npm run serve` 跳过构建，直接用现成的 `dist/` 启动。
- **存档**：学习进度写在 `progress/` 里。点网页右上角的「存档」，会把 `progress/` 提交到 Git（只提交这个目录），提交信息自动写出这段时间学了什么。默认不自动提交。

网站上有这些：

- **首页**：上面是知识星图，下面是全部小节的列表。
  - 星图有立体、平面两种看法，一键切换，往右越深。
  - 能学的星微微发光，学完的是实心，标了「已会」的带圈，还够不着的是暗的，还没写的是虚线圈；写好但还没审的，节点上方有个小橙点。
  - 点一颗星进入那一节。
- **小节页**：讲解、例题、几何图像和动画，最后是 8 道题，简单、中等、难、思考各 2 道。
  - 简单题、中等题当场判对错，每题有 3 级提示。
  - 难题、思考题记状态和思路笔记。点「复制给 Claude」拿去批改，再把批改结果录回来。
  - 带下划线的是术语。电脑上鼠标悬停、iPad 上点一下，弹出浮窗：简介，以及定义它的那一节；那一节还没学的话，浮窗会提醒你。
- **复习**：顶栏的「复习」收录标了「没把握」、答错过、看过提示的题。
- **内容有误**：在网页上标出来，记进 `content/issues.yaml`，写内容 agent 下一批处理。
- **动画组件画廊**：`/gallery`。

## 内容放在哪

```text
content/
  <学科>/<领域>/
    _domain.yaml        领域名、证明深度、符号约定（KaTeX 宏）、术语表
    <小节>/
      lesson.md         文件头（id、标题、目标、前置、状态等）和正文
      problems.yaml     8 道题：题干、标准答案、3 级提示、解答
      *.svg             静态图；动态图用动画组件
  issues.yaml           你在网页上标的「内容有误」（第一次标时生成）
progress/               你的学习进度：网站写入，「存档」时提交
tools/
  verify/               审查写的验算脚本，每节一个，改题后可以重跑
  statements/           只导出题干的小工具
  migrate/              改了小节 id 或题号时的进度迁移脚本，由你运行
docs/
  plan.md               方案：规矩、流程、每批记录、给各 agent 的提示词
  reviews/              审查报告，每批每个领域一份
```

- 小节的 id 就是路径的三段：`content/math/analysis/completeness/` 是 `math.analysis.completeness`。
- 小节有三种状态：`outline`（只有目录）、`written`（写好，待审）、`reviewed`（审过）。
- 正文是 Markdown，公式写成 `$…$`。术语写成 `:term[上确界]{id="math.analysis.supremum"}`，下定义的那一段前面加 `::anchor{id="def-…"}`，动画写成 `:::anim{component="function-plot"}` 块。YAML 里给人看的文字一律用块写法 `|`。
- 细则见 plan.md 的「内容模型」「每节固定结构与写作规范」「题目与判题」「附录：动画组件参数」。

## 代码放在哪

| 目录 | 是什么 |
| --- | --- |
| `compiler/` | 内容编译器：校验内容、用 KaTeX 编译公式、算前置图的层级，输出到 `generated/`（不提交） |
| `src/` | 网站前端（React + Vite + TypeScript）：星图、小节页、判题、复习、笔记 |
| `shared/` | 编译器和网站共用的代码，如判题用的表达式求值 |
| `server/` | 进度服务（Fastify）：读写 `progress/`，「存档」时调用 `git` 提交 |
| `packages/anim/` | 动画组件：函数图像、向量场、相图、振子、线性变换 |

## 内容是怎么写出来的

内容分批写。每一批由三类会话合作：写内容 agent 写；审内容 agent 审，和写的不是同一个会话；写代码 agent 安排批次、核对、提交，并把新定下的规矩写回 plan.md。

1. 写内容 agent 按 plan.md 的规范写一批小节，状态改成 `written`。
2. 审内容 agent 逐节审。讲解和例题看对不对；简单题、中等题用 `npm run statements` 只看题干，自己写脚本独立验算；难题、思考题读参考解答。报告写进 `docs/reviews/`。
3. 写内容 agent 按报告修订；审内容 agent 复核，通过的小节改成 `reviewed`。
4. 每个领域一个提交；审查定下的新规矩写回 plan.md，单独提交。

构建时还有一层硬校验：字段和格式、公式能不能渲染、前置关系有没有环、术语标记在不在术语表里。不通过就报错，内容进不了网站。

## 常用命令

| 命令 | 做什么 |
| --- | --- |
| `npm start` | 构建网站并启动服务，只对本机开放，端口 3141 |
| `npm run start:lan` | 同上，对局域网开放，给 iPad 用 |
| `npm run serve` | 不构建，用现成的 `dist/` 启动 |
| `npm run dev` | 开发服务器，端口 5173，改了代码或内容自动刷新 |
| `npm run build` | 编译内容，构建网站到 `dist/` |
| `npm run content` | 只编译、校验内容；`npm run content:watch` 监听 `content/` 自动重编 |
| `npm run verify` | 跑 `tools/verify/` 下的全部验算脚本，和标准答案比对 |
| `npm run statements -- [范围…] [--tier easy,medium]` | 只导出题干；范围写学科、领域或小节的 id，不写就是全部 |
| `npm test` | 单元测试（Vitest） |
| `npm run typecheck` | 类型检查 |

`npm start`、`npm run start:lan`、`npm run serve`、`npm run dev` 用的都是这个仓库里真实的 `progress/`：打开小节、看提示、作答都会留下记录。

## 在这个仓库里干活的 agent 请注意

- **plan.md 是唯一依据**。新定的规矩写回 plan.md 对应的小节，不另起文档。撤不回的决定（影响数据格式、进度文件、id 的）先停下来问。
- **不碰 `progress/`**：那是真实的学习记录，不改，也不提交。
- **页面检查只用进度写临时目录的服务**，不用 `npm run dev`、`npm start`、`npm run serve`：

  ```bash
  npm run build
  node --import tsx server/main.ts --port 3142 --data <临时目录>
  ```

  这个服务读的是 `dist/`，改了内容要先重新构建。要试「存档」，先在临时目录里 `git init`。查完用 `git status progress/` 确认没动过。
- **含反斜杠的文件用编辑工具写，不经过 shell**：Claude Code 的 Bash 工具会把命令里的 `\\` 变成 `\`，公式就坏了。
- **小节进入 `written` 以后，id 和题号不能随便改**：改名、拆分、换题都要附进度迁移脚本，放进 `tools/migrate/`，由用户运行。
