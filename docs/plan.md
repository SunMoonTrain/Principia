Nov 8, 2026 · @MoonTrain Sun

## 怎么用这份文档

先审方案，再开工：审方案 agent 只挑「规则没说清的地方」，你拍板后再把写代码提示词发出去。

1. 把这份文档导出成 Markdown，放进新仓库的 `docs/plan.md`。之后由写代码 agent 维护这份方案，写回规则见下一节「写回方案的规则」。
2. 把文末「给审方案 agent 的提示词」连同 `docs/plan.md` 发给审方案 agent。它列出问题和选项，由你决定，再由写代码 agent 把决定写回 `plan.md` 正文。
3. 把「给写代码 agent 的提示词」发给写代码 agent，从开发台阶 1 开始。每完成一级，它截图汇报，你验收后再放行下一级。
4. 开发台阶 8、9（内容批次）由写内容 agent 和审内容 agent 执行，两者必须是两个独立会话，提示词见文末。

## 写回方案的规则

这份方案是三个 agent（写代码、写内容、审内容）共同的唯一依据，而写内容和审内容的 agent 只读正文，所以决定必须写进正文对应的小节，不要只记在文末。

- 你拍板的决定，由写代码 agent 写回正文对应的小节。
- 执行中遇到方案没说清的地方，先判断猜错后能不能撤回：
  - 「撤不回」或「撤回成本高」的（包括影响数据格式、进度文件、id 的），停下来问你；
  - 「能撤回」的，直接按自己的推荐定下来、写进正文对应的小节，并在汇报里单独列一节「我替你定的」，供你事后过目。
- 三个 agent 都按这条规则办。写内容和审内容 agent 对 `plan.md` 的改动，并进当批的内容提交。

## 总览

这是一个只给自己用的本地学习网站：数学和物理的主要领域，切成一级一级的小节，内容由 agent 提前写成文件，网站负责显示、判题、记录进度。

**直观图像**：一张立体的「知识星图」。每个小节是一颗星，前置关系是星之间的连线，越往上越深。学完的星是亮的，前置都学完、现在能学的星在微微发光，还够不着的星是暗的。点一颗星，就走进那一节。

**一句话记住**：内容是文件，网站是播放器，进度是一份能提交到 Git 的存档。

**整条流水线**：

1. 写内容的 agent 按规范写出小节文件（讲解、例题、8 道题）。
2. 审内容的 agent（和写内容的不是同一个会话）逐节校对：讲解和例题的正确性，简单题、中等题的答案用脚本独立验算，难题解答抽查。
3. 构建脚本做硬校验：格式、公式能否渲染、前置关系有没有环。不通过就报错，不进网站。
4. 网站显示星图和小节；简单题、中等题当场判对错；难题、思考题只做标记和思路笔记，你拿去找 Claude 批改。
5. 进度由一个本地小服务写进 `progress/` 目录的文件里，你点「存档」时提交到 Git。

**范围之外**：账号、联网同步、网页里接 AI 批改，第一版都不做。

## 内容模型

内容分三层：学科 → 领域 → 小节；小节之间用「前置」连成一张有向无环图，可以跨领域、跨学科连。

**为什么用 Markdown 加 YAML（一种缩进式的配置文本格式）**：agent 写起来自然，公式直接写在正文里；Git 对比差异时人能看懂；你自己也能顺手改错字。

**一级台阶 = 一个小节**：读完讲解和例题要 20 到 30 分钟（不含做题时间，文件头的 `minutes` 也是这个口径），只引入 1 到 2 个新概念。太大的小节必须拆开。

**前置只列最少的直接前置**：能通过别的前置间接推出的不列。审查「是否缺前置」时，沿整条前置链查。构建发现能由别的前置推出的前置时给警告。把别的领域里讲过的内容严格化的小节（例如数学分析里证明单变量微积分里用过的定理），把讲过它的那一节也列为前置（批次 0 定的）；物理里换一种方法重讲别的领域讲过的结论（例如循环坐标那一节用拉格朗日量重讲有心力的降阶），同样把讲过它的那一节列为前置（批次 1 审查时定的）；那一节已经能由别的前置推出时不再重复列，免得构建警告（批次 0 审查时定的）。写正文时发现讲解要用的概念不在前置链上，写内容 agent 可以给本领域的小节补前置或换前置（id 不变，层级可能跟着变），在汇报里列出，由审内容 agent 核对（批次 1 定的）。

目录结构：

```text
content/
  issues.yaml               你标记的「内容有误」（只由网站写入）
  issues-resolved.yaml      写内容 agent 记下的处理结果（只由写内容 agent 写入）
  math/
    analysis/
      _domain.yaml          领域信息、证明深度、符号约定（KaTeX 宏）、术语表
      completeness/
        lesson.md           文件头 + 这一节要回答的问题、讲解、几何图像、例题、常见误区（可选）
        problems.yaml       8 道题
        *.svg               静态图（动态图用动画组件）
  physics/
    lagrangian-mechanics/
      ...
progress/                 你的进度（见「进度存储」）
tools/
  verify/                 审内容 agent 的验算脚本，保留在仓库里，改题后可重跑
  migrate/                进度迁移脚本（做改动的 agent 写，你运行）
  statements/             只导出题干的小工具：npm run statements -- <范围> [--tier easy,medium]
docs/
  plan.md                 本方案
  reviews/                审内容 agent 的审查报告，每批一份
```

学科、领域、小节的目录名就是 id 的三段，只用小写英文字母、数字和连字符，以字母开头。学科目录没有单独的信息文件，显示名（数学、物理）由网站提供。

小节文件头（`lesson.md` 开头的 YAML 段）：

```yaml
id: math.analysis.completeness     # 全局唯一：学科.领域.小节，必须和路径一致
title: |
  实数的完备性
goal: |
  知道实数轴「没有洞」指什么，会用确界原理论证简单命题。
prerequisites: [math.analysis.sequences-limits]
minutes: 25                        # 只算读讲解和例题，不含做题
summary: |
  实数轴上没有洞：有上界的集合一定有最小上界。
status: written                    # outline（只有目录）| written | reviewed
proofPolicy: sketch                # 可省略；写了就覆盖 _domain.yaml 里的值
```

**按 status 规定必填字段**：

| status | 必填 |
| --- | --- |
| outline | `id`、`title`、`goal`、`prerequisites`、`status` |
| written、reviewed | 全部字段（`proofPolicy` 除外，它可以省略），外加 `problems.yaml` 里的 8 道题 |

- `goal` 是一句话目标，批次 0 就写；`summary` 是一句话总结，等写正文时才填。
- `status` 为 `outline` 时，正文和 `problems.yaml` 不编译也不显示（写了的话构建只警告）；这样的小节页只显示标题、「待写」、`goal` 和前置回顾。
- 文件头、`problems.yaml`、`_domain.yaml` 里出现方案没列出的字段，构建报错，免得拼错的字段名被悄悄忽略。
- **id 规则**：id 既写在文件头，也由路径推出（`content/math/analysis/completeness/` → `math.analysis.completeness`），构建检查两者一致。小节的 `status` 一旦不再是 `outline`，id 就不能再改；改名或拆分时，必须附一份进度迁移脚本。还是 `outline` 的小节可以改名或拆分（审目录把 id 定下来以后也可以），但只要 `progress/` 里有它的记录（例如你标过「已会」），也要附迁移脚本，所以改之前先查 `progress/`；领域改名等于给其中每一节改名。题号同理：`written` 之后，题目调换位置、删掉，或在原位换成另一道题，都算改号，要附迁移脚本；只改标准答案（`answer.value`），或给选择题调整选项顺序、增删选项，也算换题。一批内容第一次提交之前（审查和修订期间）改题，先查 `progress/`：没有这些题的记录，不算改号、不用迁移脚本；有记录照常附脚本（批次 1 审查时提的，你定的）。迁移脚本由做改动的 agent 写，放进 `tools/migrate/`；agent 不运行它，由你运行，改过的进度随你的存档提交。

**YAML 写法**：所有给人看的文字或含 LaTeX 的字段（`title`、`summary`、`goal`、`statement`、`hints` 的每一条、`solution`、`reference`、`options` 的每一项、`unit`、术语表的文字字段、KaTeX 宏的定义、动画滑块的 `label` 等）一律用块写法 `|`。原因是双引号会把 `\theta` 里的 `\t` 当成转义吃掉，不加引号时「冒号+空格」会报错、「空格+#」后面会被当成注释删掉。id、枚举值（如 `tier`）和数学表达式字符串（如 `value`、动画里的方程）不算文字字段。构建时检查：文字字段解析出来后，出现换行以外的控制字符（如制表符）就报错。构建同时检查文字字段必须是块写法（`|`、`|-` 都算），不是就报错：双引号会把 `\nu`、`\neq` 里的 `\n` 吃成换行，换行不算控制字符，单靠上一条查不出来。

题目文件（`problems.yaml`）：每节恰好 8 道题，题号 p1 到 p8，顺序固定为 p1、p2 简单，p3、p4 中等，p5、p6 难，p7、p8 思考，由构建强制检查。一题示例：

```yaml
- id: p1
  tier: easy                       # easy | medium | hard | thinking
  statement: |
    求 $\sup\{1-1/n : n\in\mathbb{N}\}$。
  answer:
    type: number                   # number | tuple | set | choice
    value: 1                       # 可以写表达式，如 pi/2、sqrt(2)
  hints:                           # 恰好 3 条；「方向」「关键步骤」「完整解答」这些前缀由界面加，这里不写
    - |
      这个数列是单调的吗？
    - |
      任意小于 1 的数都会被某一项超过。
    - |
      ……
  solution: |                      # 答对或放弃之后显示
    ……
```

其他题型只列和上例不同的字段：

```yaml
# 写了精度要求、带单位的数值题
statement: |
  单摆摆长$L = 1\,\mathrm{m}$，取$g = 9.8\,\mathrm{m/s^2}$，求小角度下的周期，结果保留三位有效数字。
answer:
  type: number
  value: 2*pi*sqrt(1/9.8)
  unit: |                          # 可省略；写了就显示在输入框旁边
    $\mathrm{s}$
tolerance: { rel: 5.0e-3 }         # 题面写了精度要求就必须写，否则构建报错；没写精度要求时可省略，用默认值
```

```yaml
# 选择题
answer:
  type: choice
  multiple: true                   # true 多选，false 单选
  options:
    - |
      $\mathbb{R}$的每个有上界的非空子集都有上确界
    - |
      $\mathbb{Q}$的每个有上界的非空子集都在$\mathbb{Q}$中有上确界
    - |
      单调有界数列在$\mathbb{R}$中收敛
  value: [1, 3]                    # 选项序号，从 1 开始；单选只写一个数
```

```yaml
# 难题、思考题：没有 answer 和 solution，多一个只给审查用的参考解答
reference: |                       # 网页上不显示，「复制给 Claude」时也不带
  ……
```

`tuple` 和 `set` 的 `value` 写成列表，例如 `[1, sqrt(2)]`。

选择题必须写 `multiple`；单选的 `value` 写一个数（写成只含一个数的列表也行）。选项在页面上依次标为 A、B、C……，提示和解答里提到选项时用这些字母。`tolerance` 只给数值题（number、tuple、set）；选择题、难题、思考题写了会报错。写 `tolerance` 时 `rel`、`abs` 至少写一个，没写的那个用默认值。难题、思考题必须有 `reference`，不能有 `answer`、`solution`。

领域文件（`_domain.yaml`）：

```yaml
id: math.analysis
title: |
  数学分析
proofPolicy: full                  # sketch | full，小节文件头可以覆盖
macros:                            # 符号约定，做成本领域的 KaTeX 宏
  \R: |
    \mathbb{R}
glossary:
  - id: math.analysis.supremum     # 学科.领域.术语
    zh: |
      上确界
    en: |
      supremum
    abbr: |                        # 可省略
      sup
    brief: |                       # 一到两句，不超过 60 字（按「字数规则」数）
      有上界的非空实数集的最小上界，记作$\sup A$。
    definedIn: math.analysis.completeness
    anchor: def-supremum           # 定义段落的锚点，见「术语规范」
```

- **证明写到多深（`proofPolicy`）**按领域定，单个小节可以在文件头覆盖：
  - `sketch`：讲解只给证明思路，完整证明放进难题或思考题；
  - `full`：讲解里给完整证明，用于读者不看证明几乎想不到的领域或定理。
- 批次 0 由写内容 agent 为每个领域提出 `proofPolicy` 的取值，你审目录时一起定（已定，取值以各领域的 `_domain.yaml` 和小节文件头为准）。
- 各领域的 `_domain.yaml` 在批次 0 由写内容 agent 建立；`math.analysis` 在台阶 1 的样例基础上补全。写内容 agent 写到新术语时，同步写好术语表条目和定义锚点。
- 符号宏的名字在所有领域通用（批次 0 定的）：同一个宏名在哪个领域都是同一个意思，别的领域要用时照抄定义。数集 `\R`、`\Q`、`\Z`、`\N`、`\C`；正体的微分号 `\dd`（写 `\dd x`）；导数 `\dv{f}{x}`、偏导数 `\pdv{f}{x}`；粗体矢量 `\vb{v}`、单位矢量 `\uv{r}`；散度 `\divg`、旋度 `\curl`、拉普拉斯算子 `\lap`（$\nabla^2$）；转置 `A\T`；狄拉克符号 `\ket`、`\bra`、`\braket`、`\expval`、`\comm`；实部、虚部 `\Re`、`\Im`（显示成 Re、Im）。自然对数的底 $e$ 和虚数单位 $i$ 用斜体，不设宏。小写希腊字母的粗体矢量（角速度、力矩、磁矩等）写 `\boldsymbol{\omega}`，不写 `\vb{\omega}`：KaTeX 的 `\mathbf` 对小写希腊字母不起作用，也不报错（批次 0 审查时定的）。`\N` 包含 0，正整数集写 `\N^+`（批次 0 审查时定的）。偏微分方程领域按数学习惯把拉普拉斯算子写成 $\Delta$，这个领域不设 `\lap`；概率写 $P(A)$，不用 `\P`：KaTeX 里它是段落符号 ¶，也不报错（这两条是批次 0 审目录时定的）。构建时检查：同一个宏名在各领域的定义必须一样（只差空白不算），不一样就报错，以用得最多的定义为准，指出不一样的那个领域和行号。

**领域清单初稿**：

- 数学：逻辑与集合、单变量微积分、分析、线性代数、多变量微积分与向量分析、常微分方程、复分析、概率论、抽象代数、拓扑、微分几何、变分法、偏微分方程、群论与表示论。
- 物理：牛顿力学、分析力学（拉格朗日与哈密顿）、振动与波、电磁学与电动力学、光学、热力学与统计力学、狭义相对论、量子力学、广义相对论。

各领域的 id（批次 0 审目录时和小节 id 一起定下来的；目录名就是 id 的第二段）：

- 数学 `math`：逻辑与集合 `logic-sets`、单变量微积分 `calculus`、数学分析 `analysis`、线性代数 `linear-algebra`、多变量微积分与向量分析 `vector-calculus`、常微分方程 `ode`、复分析 `complex-analysis`、概率论 `probability`、抽象代数 `abstract-algebra`、拓扑 `topology`、微分几何 `differential-geometry`、变分法 `calculus-of-variations`、偏微分方程 `pde`、群表示论 `representation-theory`。
- 物理 `physics`：牛顿力学 `newtonian-mechanics`、分析力学 `analytical-mechanics`（显示名只写「分析力学」）、振动与波 `oscillations-waves`、电磁学与电动力学 `electromagnetism`、光学 `optics`、热力学与统计力学 `thermal-physics`、狭义相对论 `special-relativity`、量子力学 `quantum-mechanics`、广义相对论 `general-relativity`。

审目录时改了两个显示名，id 不变：清单里的「分析」改成「数学分析」，「群论与表示论」改成「群表示论」（群论本身在抽象代数）。这样以后加实分析、泛函分析、李群与李代数这些领域时，名字不会打架（批次 0 审目录时定的）。

**研究生和前沿内容**（你在批次 0 时定的）：以后要加，现在先不写，但目录要给它们留好位置。以后既可以加新领域（研究生课程、前沿专题），也可以在已有领域里往后接更深的小节，都不用改已有的 id；领域的划分和命名不要把以后的内容堵死（例如名字别占用以后更深一层的领域该用的词）。星图横向往右延伸，更深的内容接在右边（见「立体知识图谱与动态效果」）。命名和放法（批次 0 审目录时定的）：

- 以后新开领域用课程本身的名字起 id，例如测度论 `measure-theory`、量子场论 `quantum-field-theory`。不用 `advanced-`、`graduate-`、`intro-` 这类表示程度的词：程度由星图上的位置表示；一个领域以后还会往后接内容，名字里的「入门」「高等」迟早不对。
- 在已有领域里往后接更深的小节时，用比已有小节更具体的名字（例如在 `math.ode.chaos` 之后接 `chaos-strange-attractors`），不回头给已有小节改名。
- 广义相对论里讲宇宙学的 4 节留在广义相对论；以后开宇宙学领域（`cosmology`）时，把它们列为前置。

## 每节固定结构与写作规范

每节都按同一个顺序呈现，除「常见误区」外都是必选项，共 7 个必选部分；没有前置的根节点不显示前置回顾。固定顺序的好处是：你走进任何一节都知道东西在哪，审查 agent 也能逐项检查有没有缺。

前置回顾、一句话总结、8 道题由网站根据数据自动生成，`lesson.md` 里不手写。其余部分在 `lesson.md` 里各用一个固定文字的二级标题，按下面的顺序写：`## 这一节要回答的问题`、`## 讲解`、`## 几何图像`、`## 例题`、`## 常见误区`（可选）。构建逐项检查。`lesson.md` 不允许出现固定标题以外的二级标题，出现就构建报错；讲解内部分段用三级标题。

1. **这一节要回答的问题**：一两句话说动机，先让人想知道答案。
2. **前置回顾**（自动生成）：每个直接前置小节各一句，带链接，取自前置小节的标题和 `summary`；前置小节还是 `outline` 时，用 `goal` 代替 `summary`，并标「待写」。
3. **讲解**：先例子，后定义。每个新定义都写「为什么这样定义」，再给一个反例或边界情况。定理的证明写到多深，按这一节的 `proofPolicy`（见「内容模型」）。讲解里下定义的那一段前面都要加锚点（写法见「术语规范」），定义的概念不在术语表里也要加：页面上带锚点的段落显示成定义卡片，卡片上方标出这一段定义的术语。给新概念起名的段落（「叫作……」「这就是……」都算）也是在下定义，要加锚点；定理的名字写在带锚点的定理段落里时，不用另加（批次 3 审查时定的）。讲解、例题、几何图像的说明和常见误区里提到题目时，不写出简单题、中等题的答案，只说「见 pN」（批次 3 审查时定的）；选择题的选项也不要照搬讲解、例题里已经判过的例子（批次 4 写内容时提的）；数值题也一样，不要问讲解、例题里用同一组数算过的量，例如同样参数下的迹、平衡点坐标（批次 8 审查时定的）；图和动画也一样，不要画出简单题、中等题正好要算的那组数（批次 4 审查时定的）。这一条不管的三种情况（批次 5 审查时定的）：本节讲的函数曲线本身，只能估读出一两位数的；选择题选项和判过的例子同一类、但要多想一步才认得出的；后面小节的提示、解答引用前面小节题目的结论。
4. **几何图像**：至少一张图或一个动画组件，配一两句说明它在看什么。静态图用小节目录下的 SVG 文件，用 Markdown 图片语法引用；动态图用动画组件。引用尚未实现的组件时，构建只警告，页面上显示一个占位框。只有占位框的小节，不算满足「几何图像」，不能标 `reviewed`。构建检查：这一部分至少要有一张 SVG 或一个动画组件；`reviewed` 的小节只有尚未实现的组件也报错。图片要单独占一段。SVG 构建时内联进页面：线条和文字用 `currentColor`（或不写颜色），强调色用页面变量并写上默认值，如 `var(--accent, #2563eb)`（另有 `--good`、`--muted`、`--bg`），这样亮色、暗色主题下都看得清；不能有脚本、`<foreignObject>`、事件属性和外部引用，图里的 id 构建时自动加前缀。写完在浏览器里打开这一节，用 `getBBox()` 量一遍 SVG 里的文字：不超出画布、互不重叠、不压线（批次 5 写内容时提的：图例超出画布，写图时的估算没发现）。压线的查法：沿每条线段和路径用 `getTotalLength()`、`getPointAtLength()` 每隔约 1 像素取一个点，看有没有点落进文字的边界框（各边往里缩 1 像素）（批次 5 审查时提的）。不同会话量出的字宽可能差几个百分点（批次 8 时两个会话差约 3%，同一行说明在一边没出界、在另一边出界），所以贴边的文字要留出余量，长的说明拆成两行（批次 8 修订时写内容会话提的）。用数值积分画电场线这类从源头发出的线时，出框的线也要画回来（或者从汇入的一头反向再积一组），让每个电荷连着的条数和 $|q|$ 成正比；几幅图并排、线又画到框边时，框和框之间留出空隙，免得一幅回来的线和另一幅出去的线接在一起，看着像同一条（批次 9 审查时提的）。
5. **例题**：1 到 2 道，解答里先写「为什么想到这么做」，再写推导。
6. **一句话总结**（自动生成）：显示文件头的 `summary`。不超过 30 字（按下面的「字数规则」数），由构建检查。
7. **常见误区**（可选）。
8. **8 道题**（自动生成）：2 简单、2 中等、2 难、2 思考，取自 `problems.yaml`。

**小节页的目录栏**：宽屏（电脑、iPad 横屏）时页面左侧有目录栏，上面是这一节的目录（各部分、讲解和例题等部分里的三级标题，8 道题排成一排按难度着色的小圆点），滚动时高亮当前位置；下面列出同一领域的所有小节（层级、待写、未审）。窄屏（iPad 竖屏）改为页面顶部的一行目录。

**小节之间的链接**写 id，例如 `[实数的完备性](lesson:math.analysis.completeness)`，构建检查目标小节存在。也可以带锚点：`lesson:<小节 id>#<锚点>`，目标小节不是 `outline` 时检查锚点存在。除此之外，链接只能写 `http(s)` 地址。

**字数规则**：一个中文字或一个标点算 1，连续的英文字母或数字算 1，一个公式算 1，空格不算；计数前先去掉首尾空白。一句话总结和术语简介的字数上限都按这个数。

**术语规范**：

- 术语在每一节第一次出现时写成「中文名（英文全称，缩写）」，之后才能只用缩写；有通用中文译名的术语，第一次出现时也括注英文全称，之后用中文名，不用英文缩写。「第一次出现」按每节算。没进术语表的名词（例如「不可数集」「列紧」）第一次出现也括注英文全称；题目文字（题干、选项、提示、解答）里第一次出现的新名词同样处理（批次 1 审查时定的）。很基础的词（质点、势能、周期、频率、矩阵、坐标轴这类）不用括注（批次 3 修订时写内容会话定的，复核认可）；批次 7 按同一尺度认定的还有线性无关、部分和、重根、判别式、振幅、角频率、原函数、平衡位置、复数、复平面、实部、虚部、行列式、阻尼系数、换元（批次 7 审查时确认）。链接文字是小节标题、只起「见某节」作用的（如「见[子列与致密性定理](…)」），不算这个术语第一次出现；在句子里当名词用的（如「以后要讲的[柯西收敛准则](…)」）算，后面要括注英文全称（批次 1 修订时提出，批次 2 审查时写回）。
- 正文里显式标记术语：`:term[上确界]{id="math.analysis.supremum"}`，方括号里是显示的文字，`id` 是术语表里的 id。正文以二级、三级标题为界分块（没有三级标题的部分整个算一块），每一块里术语第一次出现的地方要标记，这一块后面再出现的不用标。题目文字（`statement`、`hints`、`solution`、`options`）里也可以标，同样弹浮窗；题干、每条提示、解答、每个选项各算一块。题目文字里可标可不标，同一批里不必统一（批次 5 时定的）。构建对照术语表检查，标记了术语表里没有的术语就失败，并指出文件和行号。术语表的中文名较长时，正文里的简称（如「主轴」之于「惯量主轴」、「角速度」之于「角速度矢量」）按同一个术语 id 标记；文字和术语表的中文名（或它的简称）相同、意思却不是那个术语时不标记，如「级数收敛」的「收敛」、「黎曼和的极限」这种广义的「极限」、指几何形状本身的「环面」（批次 3 时定的）。定理、性质开头的粗体标签（如「**哈特曼-格罗布曼定理**」）里出现术语，又是这一块第一次出现时，在标签里标记，或者把标签改得不含这个词；标签里只是更长的词的一部分时不算出现，这一块后面第一次出现的地方照样要标（批次 8 写内容时提的，审查补了后半句）。
- 定义段落的锚点：在真正下定义的那一段前面单独一行写 `::anchor{id="def-supremum"}`，它标记紧接着的那一段。锚点 id 只用小写英文字母、数字和连字符，同一节里不重复。锚点后面要紧跟被标记的那一段，不能是标题。卡片只框住这一段，后面的行间公式和段落都不在卡片里：定义式、定理的结论和起名的那句话要在卡片里出现，就写进这一段，公式写成行内公式；太长的定理可以拆成几个带锚点的段落，术语指向写了名字的那一段（批次 5 审查时定的）。叙述定理的段落也可以加锚点，id 用 `thm-` 开头，定义段落用 `def-` 开头（批次 1 定的）。「解」这类每一块都会出现的基础词不进术语表，否则满篇下划线；它的定义段照样加锚点，卡片上方不显示术语名（批次 6 审查时确认）。只在一节里用到的名词（如常微分方程的欠阻尼、临界阻尼、过阻尼）可以只加锚点、括注英文，不进术语表；以后别的小节也要用时再进术语表，并按补标的规矩补（批次 7 审查时确认）。两节以上用到的名词就进术语表；要补标已经 `reviewed` 的小节、把它退回 `written`，是正常流程，不算不进表的理由（批次 10 时定的：电磁学的「自由电荷」进表，「介电常量」只在一节用，先只加锚点）。
- 每个领域在 `_domain.yaml` 里维护术语表和符号约定（例如向量用粗体、时间导数用点）；符号约定做成这个领域的 KaTeX 宏。用到别的领域的术语时（批次 4 审查时定的，以前的批次不追溯）：前置链上学过的不标记，第一次出现照样括注英文全称；前置链上没有、读者还没学过的（多半是「以后在……会讲」的旁白），查那个领域的表，标记里写那个领域的术语 id。理由：浮窗最有用的地方是读者没学过的词；链上学过的概念，别的领域的术语表里常常是更深的版本（如数学分析的「链式法则」），指过去反而让人摸不着头脑。同一个概念两个领域都要讲时（如变分法和分析力学的「完整约束」），各自在自己的术语表里定义、各自标自己的 id；规矩 C 只管借用别的领域的词（批次 5 时定的）。别的领域术语表里中学就学过的基础词（线性代数的长度、夹角、分量、平行、投影这类），借用时不按规矩 C 标；规矩 C 管的是读者还没学过的词（批次 9 审查时提的）。
- 新进术语表的术语，本领域已写的小节里第一次出现的地方也要补标；改到已经 `reviewed` 的小节，按「每批的流程」第 6 条退回 `written`，随这一批复核（批次 5 时定的）。术语名是更长的词的一部分时（如「泛函分析」里的「泛函」），不算这个术语出现（批次 5 写内容时提的）。反过来，复合词的意思就是这个术语时（「面电荷密度」之于「电荷密度」、「正电荷」之于「电荷」），整个词带标记，不要拆成「面」加带标记的「电荷密度」（批次 9 写内容时提的，审查补了判断标准）。用脚本自动加术语标记时，标完要人工看一遍：相邻的词会拼成另一个术语（「电势能精确算出」里的「电势能」）；反过来，长术语或复合词里的短术语会被单独标出来（「感应」加带标记的「电荷」，可「感应电荷」本身是术语）。查法：把每个带标记的术语和前后紧挨着的一到四个字拼起来，看是不是别的术语或复合词（批次 10 写内容、审查时提的）。
- 术语表的简介只用读者第一次用到这个术语时已经懂的概念；前面层级的领域也会用到的术语（例如数学分析的「级数」「幂级数」，单变量微积分也讲），按那一层读者懂的概念写（批次 4 审查时定的）。简介按读到定义那一节的读者写；本领域前面的小节提前提到这个术语时，那里的读者看不懂简介里的记号（例如狭义相对论的 $\gamma_u$）不算问题（批次 7 审查时定的）。

**术语浮窗**：

- 显示：正文和题目文字里标记的术语加下划线。同一块（见「术语规范」）里同一个术语只有第一次出现加下划线，这一块后面再出现时不加（即使也标记了，也按普通文字显示、不弹浮窗）。
- 触发：电脑上鼠标悬停弹出浮窗；iPad 上点一下术语弹出，点浮窗外面关闭。点术语本身不跳转，只有点浮窗里的链接才跳转。电脑上点一下术语会把浮窗固定住，直到点外面或按 Esc。
- 浮窗内容，从上到下：
  1. 术语名：中文名 + 英文全称（有缩写的话带上缩写）。
  2. 简介：一到两句话，可以含公式。
  3. 链接：「在《小节标题》中定义」，点击后跳到那一节，并滚动到定义所在的段落。
  4. 定义它的那一节你还没学（状态既不是「已完成」也不是「已会」）时，链接下方加一行：「这是第 N 层才讲的，你还没学到」。N = 层级 + 1，根节点是第 1 层。定义在本节的术语不显示这一行。
- 数据：术语表的每个条目包含 id、中文名、英文全称、缩写（可选）、简介、定义所在小节的 id、定义段落的锚点，字段名见「内容模型」里的 `_domain.yaml` 示例。跨领域引用的术语，从定义它的那个领域的术语表里取数据。
- 构建检查：
  - 正文和题目文字里标记的术语必须存在于术语表中。
  - 术语表里每个术语的定义小节和锚点必须真实存在。
  - 简介里的公式按公式校验规则检查；简介不超过 60 字（按「字数规则」数）。
  - 例外：定义小节还是 `outline` 时，不要求锚点存在，只给警告；浮窗里的链接指向那一节，并显示「待写」。

**排版规范**：

- 行内公式 `$...$`，行间公式 `$$...$$`，只用 KaTeX 支持的命令。
- 中文与英文、数字之间加空格。公式与中文之间不用手动加空格：页面显示时，构建自动在行内公式和汉字之间留一个空格（手动写了几个也归成一个）；公式挨着中文标点时不留，并且公式和紧贴它的标点不会被拆到两行（这样的公式整体不折行，很长的公式写成行间公式）。写完在 768 像素宽的窗口（iPad 竖屏，正文栏约 720 像素）里看一遍，页面不能左右滚动，放不下的行内公式改成行间公式（批次 6 审查时提的）。看之前把每道题的提示和解答全部展开，有的溢出只有展开后才出现：难题、思考题点到第 3 级提示；简单题、中等题的解答要点「放弃」才出来，会记一条放弃，所以只在进度写临时仓库的服务上点（批次 8 写内容时提的，审查补了做法）。手机宽度（375 像素）不在目标里：紧贴中文标点的长行内式在手机上会让页面左右滚动，不用在内容里逐个拆；以后要支持手机时，改代码里「公式和紧贴的标点不拆行」的规则，所有领域一起解决（批次 8 时写代码的会话定的）。
- 倍数不写「比……大（小）N 倍」「小多少倍」，这类说法有歧义；写成「是……的 N 倍」「是……的 $\frac1N$」（批次 8 修订时逐处改过，批次 10 审查时写进规范）。
- 引号用「」。句子短，一段不超过 4 句：证明段落、「这一节要回答的问题」也一样，问句也算一句（批次 1 审查时定的）；题目文字（题干、提示、解答、参考解答）也一样（批次 4 审查时定的，以前的批次不追溯）。
- Markdown 写法：正文可以用 GFM 表格；不支持 HTML 标签和脚注。术语标记和小节链接只能用在正文和题目文字（`statement`、`hints`、`solution`、`options`）里；`title`、`goal`、`summary`、术语表各字段、`unit`、滑块 `label` 只能写一段文字、强调和行内公式。普通文字里写 `a:b` 这样的冒号没问题，但 `:名字[…]`、`:名字{…}` 形式的未知标记会报错。

**公式校验**：

- 构建用 remark-math 解析出公式节点，再逐个用 KaTeX 校验（带上本领域的宏）；不先把公式抽出来。报错带文件名和行号。
- 所有会显示出来的文本都要校验，包括 `problems.yaml`、文件头、`_domain.yaml`（含术语简介）、动画参数里的标签。
- KaTeX 的警告也算失败。
- 反斜杠被吃掉（批次 3 时加的）：用 sed、shell 或脚本改文件时，`\theta` 的 `\t` 会变成制表符、`\dot` 只剩 `dot`、多行公式行末的 `\\` 只剩一个 `\`，KaTeX 照样渲染。构建查三样：lesson.md 正文里出现换行以外的控制字符，报错（YAML 文字字段原来就查）；公式里出现不带反斜杠的常见命令名（`frac`、`dot`、`sin`、`theta` 这类，三个字母以上，`max`、`int` 这类常作下标缩写的不算）、`\nabla`、`\rho` 这类连同 n、r 被吃成换行后留在行首的半截（`abla`、`ho`），或某一行末尾只剩一个反斜杠，警告。

**提示分级**：每道题 3 级提示，依次是方向、关键步骤、完整解答；这三个前缀由界面加，内容里不写。点开一级才显示下一级的按钮，并记录用到了第几级：简单题、中等题只记答对之前用到的，难题和思考题也记录。

## 题目与判题

简单题、中等题在网页里当场判；难题、思考题网页只管标记和笔记，批改找 Claude。这样判题器只需要处理有确定答案的题，不用碰没法自动判的东西。

| 档 | 每节数量 | 怎么作答 | 怎么判 | 记录什么 |
| --- | --- | --- | --- | --- |
| 简单 | 2 | 填数值、数组或选择 | 标准答案 + 容差，自动 | 尝试记录、对错（按第一次作答）、答对之前用到第几级提示 |
| 中等 | 2 | 同上 | 同上 | 同上 |
| 难 | 2 | 网页里写思路笔记 | 找 Claude 批改，手动录入结果 | 状态、笔记、每次的批改结果和批语、用到第几级提示 |
| 思考 | 2 | 同上 | 同上 | 同上 |

**四档的定义**：

- **简单**：直接用本节的一个新概念或公式，一两步得出答案，检验「看懂了没有」。
- **中等**：要把本节内容和前置知识组合起来，或多走几步推导，仍有唯一确定的答案。
- **难**：需要一段完整的推理或证明，步骤较长或要一个关键想法，交给 Claude 批改。
- **思考**：追问定义为什么这样取、结论在什么条件下失效、和别的领域有什么联系；重在想清楚，不要求唯一答案。

**答案类型**（第一版）：`number`（单个数）、`tuple`（有序的一组数）、`set`（无序的一组数）、`choice`（单选或多选，用 `multiple` 字段区分）。单位、选项、单选与多选都用显式字段表示（见「内容模型」的题目示例）。符号表达式判等以后再加，做法是在随机点上数值比较。

选择题的选项写成条件句（「……，那么……」）时，前提要写全：默认成立的条件（如「场满足麦克斯韦方程组」「对所有 $\alpha$ 都成立」）也写出来，否则按字面读的读者会被判错（批次 8 审查时定的；批次 2 的 `hamilton-jacobi` p2 也碰到过）。

**solution**：只有简单题、中等题有，答对或点「放弃」之后显示。难题、思考题不设 `solution`，完整解答就是第 3 级提示；它们的 `reference` 只是给审查用的副本，网页上不显示。

**容差规则**：输入 x，标准答案 a，满足下式即判对。默认 rel = 10⁻³，abs = 10⁻⁹，每题可覆盖。

```latex
|x - a| \le \max(\mathrm{abs},\ \mathrm{rel}\cdot|a|)
```

- 输入用数学表达式解析器求值，所以 `1/2`、`sqrt(2)`、`pi/2` 都能填。反双曲函数写 `asinh`、`acosh`、`atanh`，也认 `arsinh`、`arcsinh` 这类课本写法（批次 7 时加的）。标准答案 `value` 也可以写表达式，构建时用判题器同一个解析器求值。标准答案没有封闭形式、只能写小数时，`value` 至少写 7 位有效数字（`npm run verify` 按 $10^{-6}$ 的相对误差比对）；题面要求的精度由 `tolerance` 管（批次 4 审查时定的）。
- 单位写在 `answer.unit`，显示在输入框旁边。题面写了精度要求时，必须同时写 `tolerance`：题面出现「保留 N 位」「N 位有效数字」「精确到」这几种模式之一却没有 `tolerance`，构建报错。N 可以是阿拉伯数字或中文数字，数字两边允许有空格，例如「保留三位」「保留 3 位」都算。
- 无法解析的输入只提示格式，不算一次尝试。

**判题边界**：

- `tuple` 和 `set` 用逗号分隔输入，输入框旁边给出提示；逐个分量算容差（每个分量用各自的 |a|）；`set` 按多重集合判，重复的元素要重复写。
- 以下输入都算格式错误，只提示格式，不计尝试次数：个数不对、类型不对、算出复数、带单位。
- `number` 类型的答案不能是 ∞，构建检查。
- 答对后可以再答，但统计用第一次作答的结果；提示级数只记答对之前用到的。
- 点「放弃」记一条特殊的尝试记录，统计按「错」算。

**作答界面**（简单题、中等题）：

- 数值题只有一个输入框，回车或点「提交」。`tuple`、`set` 用逗号隔开（中文逗号也行），整个答案外面可以包一对 `()`、`[]`、`{}`；小数只能用小数点。全角括号、`π`、`√`、`×`、`÷` 会先换成解析器认识的写法。
- 选择题点选项选中，再点一次取消；单选只能选一个。什么都没选就提交，只提示格式。
- 格式错误的提示后面注明「这次不算作答」。答错时提示「不对，再想想」，可以接着答。
- 「放弃」要再确认一次（会记为答错）。答对或放弃之后显示解答，之后仍可以接着作答，统计照旧按第一次。
- 题目卡片右上角显示第一次作答的结果：首次答对、首次答错、放弃了（算错）。解答上方注明答对前看了几级提示；放弃看过解答之后才答对的不注。
- 答对时提示条弹一下、卡片边框亮一下；答错时提示条轻轻晃一下。系统设置了「减少动态效果」时都不动。

**难题和思考题的状态**：未开始 → 有思路 → 写完待批改 → 已批改（通过 / 部分 / 没过）。状态由你手动切换。

- 笔记用 Markdown 写，公式实时用 KaTeX 预览，每题一个文件：`progress/notes/<小节 id>/<题号>.md`。
- 「复制给 Claude」按钮：把题目原文、你的思路笔记、你看过第几级提示打包成一段文本，直接粘贴就能批改；不带参考解答（`reference`）。
- 批改完你手动选结果，可附一句批语。每一次的批改结果和批语都保留，不覆盖。

**作答界面**（难题、思考题）：

- 题目卡片里从上到下：题干、思路笔记、状态、「复制给 Claude」和「录入批改结果」、批改记录（新的在上）、三级提示、底下的标记按钮。右上角显示状态，已批改时带上最新结果，如「已批改 · 部分」。
- 思路笔记：没写时只有一个「写思路笔记」按钮；编辑时上面是编辑框，下面是实时预览；写过的笔记平时显示排好版的样子，点「编辑」或双击再改。停止输入约 1 秒自动保存，标题旁显示「已保存」「还没保存」或「没连上，草稿先存在这台设备上」。写法和正文一样（Markdown、`$…$`、`$$…$$`），能用本领域的符号宏；单独一行写成 `$$…$$` 的也按行间公式显示；写错的公式显示成红字，不影响别的部分。
- 状态：四个按钮依次是未开始、有思路、写完待批改、已批改。点「已批改」等于录入一次批改，因为「已批改」要带结果。
- 「复制给 Claude」的文字：先是一句请求（指出推理里的错误和漏洞，最后用通过、部分、没过之一下结论），再分段写【题目】《小节标题》第 N 题和题干原文（Markdown，公式写成 `$…$`）、【我的思路笔记】、【看过的提示】（看过前几级）；用到本领域的符号宏时，最后加【符号约定】写明它们的意思。复制后可以展开「看看复制了什么」；浏览器不让自动复制时，直接展开这段文字让你手动复制。
- 录入批改结果：三选一（通过、部分、没过），批语可省略。批语按纯文字显示，不排公式。

**任何题都能做的标记**：「没把握」（做对了但心虚）和「内容有误」（题目或答案可能错了；讲解和例题里也能标）。「内容有误」写进 `content/issues.yaml`，每条带唯一 id，记下小节、所在部分（题号，或讲解、例题等部分的标题）和你选中的原文。写内容 agent 在下一批开始前处理，处理结果记在 `content/issues-resolved.yaml`，不改 `issues.yaml`。

`content/issues.yaml` 的格式（你在台阶 4 定的）：

```yaml

  at: 2026-11-09T10:20:00+08:00
  lesson: math.analysis.completeness
  part: p3 / 解答            # 题号 / 题干、提示 N、解答、选项 X；或部分标题，如「讲解 / 有理数轴上的洞」
  quote: |                   # 你选中的原文，公式还原成 $…$；没选时省略
    偶数项从下方逼近 $1$

```

- 每道题底下右侧有「没把握」「内容有误」两个小按钮，随时都能点；「没把握」再点一次取消。
- 「内容有误」：在小节页任何地方选中一段文字，旁边会出现「内容有误」按钮；题目底下的按钮会带上你在这道题里选中的文字，没选就只记题号。弹出的小窗里可以补一句哪里不对，按 Esc 或点窗外取消。记下的原文把公式写回 `$…$`，并去掉页面在公式和汉字之间自动加的空格，和内容文件里的写法一致，方便写内容 agent 查找。

**复习列表**收录三类题：标了「没把握」的、答错过的、看过提示的。可以手动移出（你在台阶 4 定的）：移出时记下时间（`reviewDismissedAt`），之后只看这个时间以后的新情况，又答错、又看提示或又标「没把握」时重新回到列表。难题、思考题的「答错过」指批改结果是「部分」或「没过」。

- 顶栏的「复习」按钮带着题数，点开是复习列表页：按小节分组，每题显示难度、题号、在列表里的原因和题干；「去做这道题」跳到小节页里的这道题，「移出」把它移出列表。按最近一次有动静（作答、看提示、批改、标没把握）的时间排，新的在前。

## 立体知识图谱与动态效果

横向位置固定表示「多深」，往右越深；绕着中轴的位置表示「哪个领域」：这样立体感本身就有意义，顺着圆筒往右看就是往深处走，而不是一团随机漂浮的毛线。星图横着放、很宽（你在批次 0 时定的），以后加研究生和前沿内容时接着往右长。

**布局**：

- 沿轴的位置（往右）= 这一节的层级 = 从没有前置的小节出发，最长前置链的长度。构建时算好。
- 绕轴的一圈上，每个领域占一段（立体图里是圆筒上的一条，展开图里是一条横带），数学和物理各占半圈；同一领域的节点在这一段里用力导向布局微调，避免重叠。坐标在构建时用固定随机种子算好，写进全局图谱，每次打开位置都一样。
- 只画直接前置的连线（去掉能由别的线推出来的连线），图才不会糊成一片。
- 展开图的算法（台阶 5 定的，批次 0 后改成横向）：数学占圆周的 0–180°，物理占 180–360°，还没有内容的学科也留着它那半圈，以后加内容别的学科的节点不挪位置。领域在学科那半圈里按 id 排；每个领域带的宽度 = 这个领域里节点最多的那一层的节点数 + 1 行（一行的宽度 = 学科那半圈 ÷ 学科里所有领域的行数），领域带两边各空半行，所以同一层相邻两个节点至少隔整整一行，不会挤在一起。每个领域里逐层排节点：先按前置的平均位置排、再按后续的平均位置排、再按前置排一遍；挤在一起的几个以它们想去的位置的平均为中心；跨领域的前置不会把节点拉出自己的领域带。全局图谱里写：每节的展开图纵坐标 `y2d`（度）、每个领域的那一段和颜色、两个学科的半圈和一行占多少度、只含直接前置的连线。铺成平面时每个学科按自己的行数伸缩，两个学科里一行一样高。
- 立体星图的算法（台阶 6 定的，批次 0 后改成横放）：圆筒横放，沿轴的位置 = 层级 × 2.2（场景单位），往右越深。节点在离轴 7 到 12 的圆筒壳里：绕轴的角度从展开图的纵坐标出发，离轴的距离取壳中间那一段里的随机值（种子由小节 id 算出，每次一样）；然后同一层里离得比 1.2 近的两两推开，再往起点拉回一点，反复 60 次，角度不出自己的领域带。全局图谱里每节另写立体图的角度 `angle`（度）和离轴的距离 `radius`。绕轴的角度 0° 在正上方、90° 正对镜头，和展开图的纵轴同一个方向：数学那半圈正对初始镜头，物理在背面；初始镜头正对圆筒，整个圆筒横着占满画面。
- 领域颜色：色相跟着领域带在圆周上的位置走（中心角加 180°），相邻领域颜色相近；亮色、暗色主题各配一套明暗。

**节点状态**：

| 状态 | 条件 | 样子 |
| --- | --- | --- |
| 已完成 | 你点了「这节学完了」（在这里学完；可以撤销） | 亮，带领域颜色 |
| 已会 | 待写的节点，你标了「我已经会了」（这一节后来写好了仍保持「已会」；可以撤销） | 亮，但和「已完成」样子不同 |
| 可学 | 前置全部是「已完成」或「已会」 | 缓慢呼吸的光 |
| 够不着 | 还有前置既不是「已完成」也不是「已会」 | 暗，但仍可点进去，页面顶上提示缺哪些前置 |
| 待写 | 只有目录还没内容 | 虚线轮廓 |

- 计算「可学」时，「已完成」和「已会」都算前置已满足。
- 「这节学完了」按钮在小节页最后（8 道题后面）；点过以后变成「✓ 这节学完了（完成时间）」和「撤销」。首页的小节列表和小节标题旁标出「已学完」。
- 「我已经会了」在待写小节的页面上（「这一节还没写」的说明下面）；标了以后显示标的时间和「撤销」，首页列表和小节标题旁标「已会」。这一节后来写好了，页尾显示「这一节写好以前你标过「已会」」，可以点「这节学完了」，也可以撤销。
- 写好了但够不着的小节，页面顶上提示缺哪几节前置（带链接）；缺的前置还是待写时，注明「会了可以标「已会」」。
- 展开图上的样子：已完成是实心点加一圈淡光；已会是圈里一个点；可学是领域颜色的圈，外面一层缓慢呼吸的光；够不着是暗灰的点；待写是虚线圈；写好但未审的，标题后面跟一个「未审」。点亮的前置（已完成或已会）发出的连线用领域颜色，其余是淡灰。缩小看全图时不显示节点的标题（看悬停卡片），放大到看得清时才显示；标题超过 13 个字截断，完整的看卡片。
- 立体星图上的样子：已完成是领域颜色的实心球加一圈光晕；已会是领域颜色的菱形（八面体）；可学是领域颜色的球，光晕缓慢呼吸；够不着是半透明的小灰球；待写是灰色线框球；未审的在节点外侧有一个小橙点；鼠标移上去时那颗星外面出现一圈白环。圆筒上每个领域一条淡色的带，领域名写在圆筒两端（转到背面的变淡）；右端写学科名；圆筒上方标层级。
- 写好但还没审（`written`）的小节，在星图节点和小节页上标出「未审」。
- 小节页的术语浮窗也按这里的状态判断你学没学到（见「术语浮窗」）。

**交互**：旋转、缩放、平移；悬停显示标题和一句话总结（待写节点显示 `goal`，并标「待写」）；点击进入小节；按学科、领域筛选；「我现在能学什么」按钮把所有可学节点拉到镜头前；2D 和 3D 一键切换（iPad 上嫌卡就用 2D）。2D 模式是把圆筒展开铺平：横轴是层级（往右越深），纵轴是领域带。各领域不重叠，同一层的节点在领域带里至少隔一行；2D 坐标在构建时和 3D 坐标一起算好。

- 平面图：横轴是层级，往右越深，比屏幕宽也比框高，横向、上下都滚（你看了前两版说太小、点挤在一起以后改的）。缩到最小时每一层至少 90 像素宽、每一行至少 11 像素高（图大约是屏幕的三倍宽、框的两倍半高），点的直径约为行距的七成，上下两个点之间留着空；框高约窗口的四分之三。移动：滚动条、滚轮（上下）、Shift+滚轮或触控板左右滑（左右），或者按住拖动。缩放：Ctrl+滚轮（触控板双指捏合）或右下角的按钮；放大到行距约 16 像素（0.6 倍）时显示标题，这时每一层至少 190 像素宽，标题不叠；标题字号不随缩放变。点小的时候圈的线不跟着变细，待写的虚线圈改画实线细圈（不然碎成锯齿），放大到显示标题时才是虚线。左边一栏写学科和领域名、顶上一行写层级，滚动时不动。用 Tab 移到画面外的节点时，滚过去。「复位」缩到最小、回到左上角。
- 立体图：横放的圆筒。左右拖动沿着层级走，上下拖动转动圆筒（壳中间那一圈跟着鼠标），右键拖动一样；滚轮推近拉远，鼠标所在的那一层留在原处，最近推到离轴 20（还在圆筒外面）。只能绕中轴转，不再能转到任意角度看：换来的是拖动直观，横着浏览方便。
- 两种看法都有「我现在能学什么」和「复位」。「我现在能学什么」：平面图放大到看得清标题，把可学的节点挪到画面中间；立体图转到它们那一面、左右对准、推近。「复位」回到一开始的样子（立体图是全景，平面图是缩到最小、回到左上角）。

**动态效果**（克制，不抢内容）：

- 学完一节回到星图时，这颗星点亮，光沿连线流向刚解锁的节点。做法（台阶 6 定的）：每次打开星图，和上次看星图时比（上次点亮了哪些记在这台设备的浏览器里），新学完或新标「已会」的星闪一下，光沿连线流向因此变成可学的后续，流三遍；第一次看星图时什么都不放。立体图和平面图都有。
- 页面切换用镜头飞入那颗星的过渡：立体图里点一颗星，镜头用 0.65 秒飞到它跟前，再进入小节。
- 简单题、中等题答对时一个小小的反馈动效。
- 系统设置了「减少动态效果」时，只关掉星图和界面动效；小节里的动画组件改为默认暂停。星图上具体是：光晕不呼吸，没有点亮动画和镜头飞行，「我现在能学什么」「全图」直接跳过去，拖动松手就停（不带惯性）。

## 可复用动画组件库

动画做成一套独立的组件库，小节文件里只写「用哪个组件、参数是什么」。这样写内容的 agent 不用每节手写动画。动画组件就是本网站的 React 组件，3D 部分用 react-three-fiber。

**放在哪**：仓库里单独一个包 `packages/anim/`，不依赖网站的任何代码，有自己的组件画廊页（每个组件一个演示，也是测试页；在网站的 `/gallery`，首页最下面有链接）。它是独立的包，但不需要适配别的框架。

**小节里怎么用**：

```text
:::anim{component="phase-portrait"}
system: { x: "y", y: "-sin(x) - b*y" }
range: { x: [-6.3, 6.3], y: [-3, 3] }
dt: 0.01
sliders:
  - name: b
    min: 0
    max: 1
    step: 0.05
    default: 0.2
    label: |
      阻尼系数$b$
:::
```

**统一约定**：

- 内容里一律用短横线写组件名，如 `phase-portrait` 对应 PhasePortrait；每个组件的写法见附录「动画组件参数」。
- 每个组件都有参数滑块和重置；只有带时间演化的组件才有播放 / 暂停 / 速度。
- 公式以字符串传入，用数学表达式解析器编译成函数，所以内容文件能直接写 `-sin(x)`。
- 方程组用映射写法：键是状态变量，值是它对时间的导数，例如 `{x: "y", y: "-sin(x)"}`。时间变量统一叫 `t`；公式里可以直接用名字引用滑块参数。
- 滑块的结构包括 `name`、`min`、`max`、`step`、`default`、`label`；`label` 里可以写公式（按「公式校验」检查）。滑块名和 `t`、状态变量，以及 `e`、`pi`、`i`、`Infinity` 和它们的大写形式（`E`、`PI`、`I`、`INFINITY`）重名时，构建报错。`phi`、`tau` 等其他 math.js 常数可以用作滑块名，同名时以滑块的值为准（物理里 `phi` 常作相位、`tau` 常作时间常数）。函数名不算。滑块只能停在 `min` 加整数个 `step` 上，`max`、`default` 不在这些值上时构建报错；滑块旁边显示的数，位数按 `step` 和 `min` 里小数位多的那个（批次 7 时加的）。
- 需要解微分方程的统一用四阶龙格-库塔法，固定步长。步长由小节指定（`dt`）；调节速度时改变的是每帧计算的步数，不改步长。`dt` 只给要解微分方程的组件；不解微分方程的带时间演化组件（插值、抽样类），各自的速度参数在实现时定，属于数据格式，先问你。
- 速度有 0.25×、0.5×、1×、2×、4× 五档，1× 时模拟时间和真实时间一样快；卡顿时一帧最多补 0.1 秒（乘以速度），不会一下跳很远。组件不在屏幕上、页面在后台时不算。
- 参数有校验规则，小节里写错参数在构建时就报错。引用尚未实现的组件时，构建只警告，页面上显示一个占位框。组件名不在附录「各组件」表里的，构建报错。通用参数（`sliders` 的结构、重名规则和 `label` 里的公式）对所有组件都查；已实现的组件（附录里写了写法的）还查专有参数：结构、式子里的名字、个数，图例 `label` 也按「公式校验」检查。
- 系统设置了「减少动态效果」时，组件默认暂停。
- 2D 用 Canvas 画，3D 用 three.js（通过 react-three-fiber）；颜色跟随网站的亮色 / 暗色主题。

**第一批**（覆盖最多小节的几种）：

| 组件 | 看什么 | 典型用处 |
| --- | --- | --- |
| FunctionPlot | 函数图像，参数可拖 | 极限、导数、级数逼近 |
| VectorField2D | 向量场和流线 | 梯度、散度、旋度、电场 |
| PhasePortrait | 相空间轨迹 | 单摆、振子、稳定性 |
| Oscillator | 弹簧振子、耦合振子的运动 | 小振动、简正模 |

**第二批**（LinearMap2D 批次 9 时先做了，其余在台阶 10）：ParticleMotion（质点或刚体在空间里的运动和轨迹）、Wave1D（波的叠加、驻波）、LinearMap2D（线性变换如何拉扯网格）、Surface3D（二元函数曲面）、ComplexMap（复变函数如何变形平面）、Distribution（概率分布与抽样）、Construction（可拖动的几何作图）。

## 进度存储

进度由 Windows 电脑上的一个本地小服务写成文件，再由你手动「存档」提交到 Git。原因是浏览器不能随便写本地文件，iPad 上的 Safari 更不行；有了这个小服务，电脑和 iPad 打开的是同一个网站、写的是同一份文件。

**怎么访问**：Windows 电脑上运行 `npm start`（先构建网站，再启动服务），同一个服务既提供网站又提供进度接口，端口 3141。电脑上用 `http://localhost:3141` 打开。`npm start` 只对本机开放；iPad 要用时改运行 `npm run start:lan`，它会打印电脑的局域网地址，iPad 在同一个 Wi-Fi 下打开这个地址，所以 iPad 用的时候电脑得开着。第一次运行 `start:lan` 时 Windows 防火墙会弹窗，只勾「专用网络」。网站没改过时可以用 `npm run serve` 跳过构建直接启动。开发用的 `npm run dev`（端口 5173）也带着同样的进度接口，写的是同一份 `progress/`。网站文件和内容包用 gzip 压缩传输：内容包很大（一节约几百 KB，大头是 KaTeX 的输出），压缩后小很多。

**文件**：

```text
progress/
  lessons.yaml                  每节：状态（已完成 / 已会）、开始时间（第一次打开小节）、完成时间
  problems/<领域 id>.yaml       每题：尝试记录、提示级数、没把握、难题状态与批改记录，例如 problems/math.analysis.yaml
  notes/<小节 id>/<题号>.md     难题和思考题的思路笔记
```

文件名里的「领域」用完整 id，例如 `math.analysis`。「学完」可以撤销。「内容有误」不在这里，写在 `content/issues.yaml`。

**文件格式**（你在台阶 3、4 定的）：

```yaml
# progress/lessons.yaml（按小节 id 排序）
math.analysis.completeness:
  startedAt: 2026-11-08T15:30:12+08:00  # 第一次打开
  status: completed                     # completed 学完了 | known 已会 | none 撤销了
  statusAt: 2026-11-08T16:10:05+08:00   # 两台设备都改过时取较新的

# progress/problems/math.analysis.yaml（按小节、题号排序）
math.analysis.completeness:
  p1:
    attempts:            # 只追加，按 id 去重；格式错误不记
      - id: 3f2a9c1e-…   # 每条一个随机 id
        at: 2026-11-08T15:41:02+08:00
        input: '1.7'     # 你填的原文；选择题记成 AD 这样的字母
        result: wrong    # correct | wrong | gave-up
      - id: 9c1b…
        at: 2026-11-08T15:42:30+08:00
        input: sqrt(3)
        result: correct
    hints:               # 每级提示第一次点开的时间
      1: 2026-11-08T15:41:40+08:00
    unsure: true         # 没把握；取消时写 false（任何题都有）
    unsureAt: 2026-11-09T10:02:11+08:00
    reviewDismissedAt: 2026-11-10T21:00:00+08:00  # 从复习列表移出的时间
  p5:
    hints:
      1: 2026-11-09T10:10:00+08:00
    status: ready        # 难题、思考题：none 未开始 | idea 有思路 | ready 写完待批改 | graded 已批改
    statusAt: 2026-11-09T10:40:00+08:00
    grades:              # 批改记录：只追加，按 id 去重，每次都保留
      - id: 5e1d0c2a-…
        at: 2026-11-09T11:05:00+08:00
        result: partial  # pass 通过 | partial 部分 | fail 没过
        comment: |       # 批语，可省略
          第二步没说明 A+B 非空。
```

- 时间一律写本地时间加时区（如 `+08:00`）。
- 统计都由记录算出来，不另存：首次对错看第一条作答；「答对前用到第几级提示」看第一次答对之前点开过的最高一级；难题的批改结果看最新一条批改记录；复习列表见「题目与判题」。
- 合并：作答、批改记录按 id 去重后按时间排序；每级提示取最早的时间；`startedAt` 取最早；`reviewDismissedAt` 取最晚；`status`、`unsure` 取各自时间（`statusAt`、`unsureAt`）较新的。录入一条批改记录时，题目的 `status` 同时改成 `graded`（时间取批改时间，同样按较新的算）。
- 笔记文件就是你写的 Markdown 原文，没有文件头；把笔记清空就删掉这个文件。

按领域拆文件、笔记单独成文件，是为了让 Git 的差异好读，也减少整份覆盖带来的冲突。

**合并与写入**：

- 服务端按「题」合并更新，不整份覆盖；先写临时文件再改名，写到一半断电也不会损坏。
- 尝试记录只追加，每条带唯一 id 和时间（带时区），服务端按 id 去重，补交重发也不会重复计次。批改记录同样只追加，每一次都保留。
- 「没把握」「批改结果」这类状态，取时间较新的那个。
- 服务端对同一个文件排队写入。
- 两台设备改了同一题的笔记时，两份都保留，并在界面上提示：服务端发现这份笔记在你编辑期间已被另一台设备改过，就把这次的内容另存为 `<题号>.conflict-<时间>.md`。时间写成 `20261108-153000` 这种不含冒号的格式，因为 Windows 文件名不能有冒号。
- 笔记整份保存：停止输入约 1 秒后自动保存，保存时带上开始编辑时那一版的指纹（内容的哈希）；服务端算出当前文件的指纹和它不一样，就按上一条另存。另存的文件不会自动删除，题目卡片上一直提示，你对照着合并进笔记后点「删掉另存的版本」。连不上时笔记草稿也先存在浏览器里，重连后补交。
- 网页把每个改动作为一条「操作」发给服务：第一次打开小节、学完或撤销、一次作答、点开一级提示、标或取消「没把握」、改难题状态、录入批改结果、从复习列表移出、标「内容有误」。笔记不走操作，整份保存（见上面笔记那两条）。服务端逐条校验，格式不对的那一条丢掉，不连累同一批里别的；一批最多 1000 条，网页每次发 200 条。上面的合并规则让重复收到的操作不起作用，所以补交时重发是安全的。
- 浏览器缓存只是一个待发送队列：页面开着时服务中断，仍然能继续做题，记录先进队列，重连后自动补交；打开网页时以服务端为准。连不上时右上角显示「没连上进度服务 · N 条待补交」，每 3 秒重试；切回这个页面时重新读一遍服务端，看得到另一台设备刚做的题。
- 界面偏好（亮色 / 暗色主题，默认跟随系统，右上角可切换）只存在各设备的浏览器里，不算进度、不进 Git。

**已知限制**：电脑休眠或服务没开时，iPad 打不开网站。

**存档**：网页右上角「存档」按钮，执行一次 Git 提交，只提交 `progress/`。提交信息自动生成，统计「自上次存档以来」学了什么，例如「学完 2 节：实数的完备性、确界原理；做题 11 道」；做题数按题目数计，不按尝试次数。标了「已会」的另起一段，写成「标为已会 1 节：确界原理」；有新批改记录的难题也算做过的题；新写或改过的笔记另起一段，写成「写笔记 3 题」（另存的冲突版本不算）；只打开了小节、看了提示、改了状态时写「更新学习进度」。「上次存档」就是 Git 里最近一次提交的 `progress/`。提交时带上路径，只提交 `progress/`，暂存区里别的改动不受影响。没有改动时不提交，网页提示「没有新的进度，不用存档」。默认不自动提交。

**仓库安排**：`progress/` 和内容放在同一个仓库。内容由写内容 agent 提交（每批一个提交），进度由你提交，两者不碰同一批文件。`content/issues.yaml` 里你的标记，也由写内容 agent 每批提交时带上。

## 架构与技术栈

内容和进度走两条互不干扰的路：内容在构建时就校验完、编译好，网站只读；进度只在网站和本地服务之间流动。

**整体架构（6 个部分）**：内容文件 → 构建脚本（校验、编译公式、算层级）→ 内容包 → 网站前端（星图、小节页、判题、动画）↔ 进度服务（Windows 本地）→ `progress/` 与 Git。

内容一旦编译进内容包就不会在运行时出错；网站会写的只有进度，以及 `content/issues.yaml` 里的「内容有误」标记。

**模块**：

| 模块 | 输入 | 输出 |
| --- | --- | --- |
| 内容编译器 | `content/` | 每领域一个内容包、全局图谱（含层级和水平坐标）、校验报告 |
| 图谱布局 | 全局图谱（坐标已在构建时算好）+ 进度 | 节点状态 |
| 小节页 | 内容包 + 进度 | 渲染好的讲解、例题、题目、术语浮窗 |
| 判题器 | 题目定义 + 你的输入 | 对错、提示 |
| 动画组件库 | 组件名 + 参数 | 画面 |
| 进度服务 | 网页发来的更新 | `progress/` 文件、Git 提交 |

**什么变了重算什么**：改了某领域的正文或题目，只重编这个领域的内容包；改了前置关系，重算全局图谱和层级。开发模式下监听文件变化自动重编。

**技术栈**：

| 选项 | 好处 | 代价 |
| --- | --- | --- |
| React + Vite + TypeScript（建议） | agent 最熟；three.js 有成熟的 React 封装；生态最大 | 打包体积稍大，本地用无所谓 |
| Svelte + Vite + TypeScript | 轻，动画写法简洁 | agent 出错率稍高，3D 生态小 |
| Astro | 天生适合 Markdown 内容站 | 星图、判题、进度这些重交互部分要另外接，反而绕 |

建议第一项，因为这个网站最难的是星图和动画，而那正是 React 生态最强的地方。配套：

- Markdown 处理：unified 管线 + remark-math + remark-directive（处理 `:::anim` 块）+ remark-gfm（表格）。公式由构建脚本逐个交给 KaTeX 编译，校验通过的那一份输出直接用于显示，不再经过 rehype-katex：它锁定旧版 KaTeX，校验和显示可能用上两个版本。
- 数据校验：zod；数学表达式：math.js；3D：three.js 与 react-three-fiber。
- 代码目录：`src/`（网站）、`compiler/`（内容编译器）、`shared/`（编译器和网站共用的代码，如判题用的表达式求值）。编译结果写进 `generated/`（不提交 Git）：开发时网站从 `/data/` 读取，`vite build` 时拷进 `dist/data/`。
- 进度服务：Node.js + Fastify，Git 操作直接调用命令行 `git`。

## 内容生产与审查流水线

先一次性定好全部目录，再按领域一段一段地写正文。目录便宜、改起来快，先定下来星图就有全貌；正文贵，分批写才审得过来。

**批次 0：只出目录**

- 产出每个领域的全部小节：`id`、标题、一句话目标、前置关系、`status: outline`。不写正文和题目。

**分工**：一共三个 agent：写代码、写内容、审内容。开发台阶 8、9 由写内容 agent 和审内容 agent 执行。写内容和审内容必须是两个独立会话。

**每批的流程**：

1. 写内容的 agent 按「每节固定结构」写，同时写好题目、提示、术语表条目和定义锚点。
2. 构建校验必须全部通过（格式、公式、前置、术语、动画参数）。
3. 审内容的 agent 逐节检查，审查意见每批写一份报告，存进 `docs/reviews/`。审查范围：讲解和例题的正确性，简单题和中等题的答案独立验算，难题解答抽查，再加格式与清单检查。清单如下：
   - 讲解和例题：推导和结论是否正确；定义有没有「为什么」、有没有反例；一句话总结准不准。
   - 简单题、中等题：用只导出题干的小工具读题，不看答案，用脚本独立验算，和标准答案比对。验算脚本保留在 `tools/verify/`。读题的命令是 `npm run statements -- <小节或领域 id> --tier easy,medium`：只输出网页上做题时看得到的东西（题干、选项、作答方式、单位，以及本领域的符号宏），不含标准答案、提示、解答和参考解答，所以审查时不要直接打开 `problems.yaml`；验算脚本算完后由 `npm run verify` 去读标准答案比对。判断真假的选择题（「哪些说法对」「哪些数列收敛」），验算脚本在一组检验数列或例子上逐条找反例、对照真值，脚本里写明用了哪些例子。同一领域的验算脚本可以共用一个辅助文件，文件名写成 `<学科>.<领域>._<名字>.ts`（第三段以下划线开头），`npm run verify` 不把它当成小节脚本。（这两条是批次 1 审查时定的）标准答案是某个极限值时（例如参数无限缓慢变化时的浸渐不变量），验算脚本直接模拟这个过程（参数变得足够慢），和手推的精确值核对时容差可以放宽，在脚本的 `notes` 里写明取了多慢；和标准答案比对的仍是手推的精确值（批次 2 审查时定的）。标准答案是一个极值（「最大可能是多少」「最小能是多少」）时，验算分两半：算出界，再拿一个满足全部条件的具体例子核对这个界取得到（批次 3 审查时定的）。
   - 难题：抽查解答是否正确。
   - 难度档：是否符合「题目与判题」里四档的定义。
   - 证明深度：是否符合这一节的 `proofPolicy`。`full` 的小节，主线定理在讲解里证完；没标定理、后文只引用结论的旁支结论，可以把证明放进难题，讲解里注明「证明见 pN」（批次 3 审查时定的）。`sketch` 的小节略去证明、说「道理和某处一样」时，链接要指向用的是同一个道理的地方；那里的道理不同（例如靠通解公式），就用一句话说出真正的道理（批次 7 审查时提的）。
   - 术语：每节第一次出现是否写了全称（有通用中文译名的也括注英文全称）；每个三级标题下（没有三级标题的部分按整个部分算）第一次出现是否都做了标记；符号是否符合领域约定；术语表的简介是否准确，锚点是否落在真正下定义的那一段。
   - 前置：讲解里用到的概念是否都在前置链上（沿整条前置链查）；`prerequisites` 是否只列了最少的直接前置。讲解、例题和题目文字都查；题目文字里用到前置链外的结论时，加链接注明出处即可（批次 2 审查时定的）；链接要指向真正定义这个词、证明这个结论的那一节，用术语表的 `definedIn` 核对，不要按名字猜（批次 9 审查时提的）。以这一批为直接前置的已写小节，也顺带查一遍：它们用到的这一批的概念，要在它们自己的链上（批次 9 审查时提的：变分法 `direct-methods` 写的时候前置还是大纲，用了链上没有的对称矩阵、可逆）。讲解里为了列出例子的式子而用到别的学科的结论（例如变分法里由机械能守恒得到的 $v=\sqrt{2gy}$），写明是什么结论、链接出处即可，不列为前置；这一节要讲解或推导这个结论本身时才列。`sketch` 的小节，推导里引用的分析定理（例如积分号下求导），写明条件、说明这里满足，并链接到严格证明所在的小节，可以不列为前置；读者要先懂才看得懂这一段的概念，仍要列为前置（这两条是批次 4 审查时定的）。`sketch` 的小节用到一元结论的直接推广（二元函数的连续性、有界闭矩形上的连续函数有界），或者把另一个变量固定、对 $y$ 求导（写作 $f_y$）时，说清意思、链接一元的那一节即可，不列多变量微积分为前置；要用多元复合函数的链式法则、多元泰勒公式时仍要列（批次 6 审查时定的）；交换二重积分（包括反常二重积分）的次序也要列 `math.vector-calculus.double-integrals`（批次 7 审查时定的）。本领域后面小节的术语可以提前提到（加标记、括注英文，浮窗会注明是第几层讲的），讲解和例题的推理不能用到它（批次 7 写内容时提的，审查认可）。
   - 格式：固定结构、排版规范。
4. 写内容的 agent 按报告修订：重要的必须改，小问题改掉或写一句不改的理由，逐条写进报告里「复核」前面的「修订说明」一节（批次 1 定的）；审内容的 agent 复核修订，通过后把 `status` 改为 `reviewed`（几何图像只有占位框的不能标）。内容要等复核通过才提交，复核时 `git diff` 比不出这一轮改了什么：审内容的 agent 初审时先把要审的文件拷一份快照到自己的 scratchpad，复核时和快照比（批次 7 审查会话提的）。
5. 写内容的 agent 把这一批作为一个 Git 提交提交上去；审查报告、审内容 agent 改的 `status`、`content/issues.yaml` 里新增的标记也并进这个提交。
6. 你学的时候点「内容有误」，写进 `content/issues.yaml`。下一批开始前，写内容的 agent 先处理其中未解决的条目，处理完一条就在 `content/issues-resolved.yaml` 里记一条，不改 `issues.yaml`。改到已经 `reviewed` 的小节时，把它的 `status` 退回 `written`，由审内容 agent 复核。

## 常见坑

下面这些坑都在对应步骤里提前堵住，不靠事后修。

| 现象 | 原因 | 在哪一步避免 |
| --- | --- | --- |
| 公式显示成红字 | 用了 KaTeX 不支持的命令；或 Markdown 把 `\\`、`_` 先吃掉了 | 构建时用 remark-math 解析出公式节点，逐个用 KaTeX 编译，警告也算失败，报出文件名和行号 |
| 对的答案被判错 | 容差太紧；`1/3` 之类的输入解析不了；单位不一致 | 统一用表达式解析器求值；题目写明单位与精度 |
| 标准答案本身是错的 | agent 心算出错 | 审查时用脚本独立重算 |
| 星图糊成一团毛线 | 纯力导向布局是随机的；连线太多 | 高度固定为层级；领域分区；只画直接前置 |
| iPad 上星图卡顿 | 节点多、特效重 | 节点用实例化渲染；限制帧率；提供 2D 模式 |
| 进度丢失或互相覆盖 | 两台设备整份覆盖写入；服务没开 | 按题合并写入；先写临时文件再改名；浏览器缓存兜底 |
| 动画越跑越歪 | 简单欧拉法步长大，能量漂移 | 统一四阶龙格-库塔法、固定步长；测试里检查能量漂移 |
| 前置关系出现环 | 手写依赖时互相引用 | 构建时检测环并报出具体是哪几节 |
| 小节像爬山 | 一节塞了太多新概念 | 规定 20 到 30 分钟、1 到 2 个新概念；审查清单里检查 |
| 满屏没解释的缩写 | agent 写顺手了 | 术语规范写进提示词；审查清单逐项检查 |
| 每写一批内容测试就坏，测试越跑越慢 | 测试拿真实内容的措辞、题目做断言，每条还拷一遍整个 `content/` | 编译器测试用冻结的样例 `compiler/fixtures/sample`，别的工具的测试用测试自己摆的小内容；真实内容只测「整体能通过构建」（批次 1 时定的） |

**Windows 上额外的坑**：

| 现象 | 原因 | 在哪一步避免 |
| --- | --- | --- |
| 写进度时偶尔报 EPERM | 临时文件改名覆盖时，目标文件正被杀毒软件或编辑器占用 | 改名失败时间隔几十毫秒重试几次 |
| YAML 和 Git 差异满屏变化 | Git 自动把换行转成 CRLF | 仓库加 `.gitattributes`，统一 LF |
| 小节 id 和路径对不上 | 反斜杠路径、盘符大小写 | 代码里用 `path` 模块拼路径；从路径推 id 时先转成正斜杠的相对路径，再和文件头的 id 比对 |
| npm 脚本跑不起来 | 写了 bash 专用语法（`rm -rf`、行内环境变量） | 用 Node 脚本或跨平台工具 |
| 公式里少了反斜杠，构建却通过 | 这台机器上 Claude Code 的 Bash 工具会把命令里的 `\\` 变成 `\`，单引号、加了引号的 heredoc 里也一样；sed 把 `\t`、`\d` 当成转义；Python 字符串里 `\f`、`\t` 是转义 | 含反斜杠的文件用编辑工具写，不经过 shell；构建查控制字符和不带反斜杠的命令名（见「公式校验」，批次 3 时加的） |

**第一批组件的写法**（你在台阶 7 定的）。所有式子都能直接用滑块名；`label` 一律用块写法 `|`，可以写公式（按「公式校验」检查）。参数写错、式子里用了不认识的名字，构建报错并指出行号。组件画的坐标轴名和正文的记号不同时（`function-plot` 的横轴写作 x，`oscillator` 曲线图的纵轴写作 x），说明里交代「图上写作 x」（批次 6、7 的做法，批次 7 审查时写回）。画面的范围要和滑块配套，所有组件都一样：滑块拖到两端时，讲解里描述的现象和要读者看的线、点、轨迹仍要在画面里，轨迹中途冲出画面也算不配套；写的时候把各个起点在滑块两端的运动范围算一遍（FunctionPlot 那一条的推广，批次 8 审查时定的；批次 7 的 `laplace-transform`、批次 8 的 `limit-cycles` 都是这一类）。

式子的写法（所有组件通用）：四则运算、乘方 `^`、括号，`2x` 这样的省略乘号也行；函数有 `sin` `cos` `tan` `asin` `acos` `atan` `atan2` `sinh` `cosh` `tanh` `asinh` `acosh` `atanh` `exp` `ln` `log`（一个参数是自然对数，`log(x, b)` 以 b 为底）`log10` `log2` `sqrt` `cbrt` `abs` `sign` `floor` `ceil` `round` `min` `max` `hypot` `pow` `mod`；常数有 `pi`、`e`、`tau`、`phi`（和滑块重名时以滑块为准）。求和写 `sum(k, 下限, 上限, 式子)`，连乘写 `prod(k, 下限, 上限, 式子)`：k 取下限到上限之间的整数，上下限可以用滑块和变量（如数列的 `n`），k 是新起的名字，不能和变量、滑块、常数重名；上限小于下限时和是 0、积是 1；一次超过 10000 项时算作没有定义。例如傅里叶级数的部分和 `4/pi * sum(k, 1, N, sin((2k - 1)*x) / (2k - 1))`（批次 4 时加的，组件画廊里有演示）。

FunctionPlot：画曲线、数列和点，没有时间演化。

```yaml
:::anim{component="function-plot"}
range: { x: [0, 40], y: [0, 1.1] }   # 横轴、纵轴的显示范围，必填
functions:              # 曲线 y = f(x)，变量是 x；可省略
  - expr: "1 - eps"
    label: |            # 图例，可省略
      $y=1-\varepsilon$
sequences:              # 数列：只在整数 n 上画点，变量是 n；可省略
  - expr: "1 - 1/n"
    n: [1, 40]          # 从第几项画到第几项（整数）
    label: |
      $a_n=1-\frac{1}{n}$
points:                 # 标出的点，坐标可以用式子；可省略
  - { x: "a", y: "a^2" }
sliders: [...]
:::
```

- `functions` 和 `sequences` 至少要有一种。滑块名不能叫 `x`、`n`。
- 数列可以加 `step`（正整数，可省略，默认 1）：只画 $n_0$、$n_0+\text{step}$、$n_0+2\,\text{step}$……这些项，画子列时用。比如 `n: [2, 40]` 加 `step: 2` 只画偶数项，`n: [1, 39]` 加 `step: 2` 只画奇数项（批次 1 时加的）。
- 式子在某处算出来没有定义（负数开平方、除以 0 等）：曲线在那里断开，数列的那一项不画。
- 数列画到第几项、画面的范围（`range`）都要和滑块的范围配套：滑块拖到两端时，讲解里描述的现象和要读者看的线、点仍要出现在画面里（例如 $\varepsilon$ 取最小值时，第一个进入带子的项也要画出来；参数取最大值时，横线不能跑出纵轴的范围）（批次 1 审查时定的，批次 2 审查时补了画面范围）。
- 鼠标移到图上，图例里显示各条曲线在那一处的值（数列取最近的整数 `n`，这个 `n` 不是它画出的项时不显示；算出来没有定义时显示「无定义」）。
- FunctionPlot 不按两轴等比例画：画布高约为宽的 0.6（最高 420 像素），坐标范围按这个框拉伸。要让斜率为 1 的线画成 45°（例如时空图里的光线），把纵轴范围取成横轴范围的 0.6 倍；从手机到电脑，画出来在 43.3° 到 44.6° 之间，电脑上画布宽 730、高被限在 420 时最低（批次 6 时写内容会话发现的，审查时量了三种宽度）。

PhasePortrait：二维相平面上的轨迹。图上画方向场的小箭头；轨迹是跑动的点加尾迹；在图上点一下，就从那里放一条新轨迹。

```yaml
:::anim{component="phase-portrait"}
system: { x: "y", y: "-sin(x) - b*y" }   # 恰好两个状态变量，名字自己取；值是它对 t 的导数
range: { x: [-6.3, 6.3], y: [-3, 3] }      # 键和 system 的一样
dt: 0.01
initial:                 # 一开始就放的轨迹起点，按 system 里变量的顺序写；可省略
  - [1, 0]
  - [3, 0]
sliders: [...]
:::
```

- `initial` 最多 12 个；图上同时最多 12 条轨迹，再点就去掉最早点出来的那条。
- 改了滑块，所有轨迹（包括点出来的）从各自的起点、`t = 0` 重新开始，方便比较不同参数下的相图；「重置」还会去掉点出来的轨迹。
- 两个范围的比例不太悬殊时，两轴等比例画（圆画出来是圆）；太悬殊时按固定的宽高比画。VectorField2D 也一样。
- 尾迹 `trail`（可省略）：默认 `fade`，只留最近 8 个单位时间的尾迹，越早越淡；轨迹一直往前算，跑出画面约 8 秒后画面上只剩方向场，要点「重置」重放。`full`：整条留着、不变淡，轨迹跑出画面就停（离上一个记下的点不到显示范围的千分之一就不记，一条最多两万个点，到了也停）；适合画解曲线，不适合在画面里一圈圈绕的轨迹（批次 6 审查后加的）。
- 状态变量不能叫 `t`（`t` 是时间）。画一阶方程 $y'=f(x,y)$ 的方向场和解曲线，写成 `{ x: "1", y: "f(x, y)" }` 并加 `trail: full`：$x$ 随时间匀速增加，点出来的轨迹就是解曲线。讲解里自变量叫 $t$ 时，要交代图上的横轴 $x$ 就是 $t$（批次 6 时写内容会话提的）。
- 式子里可以用时间 `t`，受周期驱动的系统（如杜芬振子）就这样画。这时方向场的小箭头按当前时刻画，会随时间变，轨迹也不沿着某一时刻的箭头走，说明里要交代（批次 8 时写内容会话提的，审查看过画面）。

VectorField2D：二维向量场。图上画箭头网格，粒子沿流线跑，跑出范围或到了寿命就在随机位置重新出现。

```yaml
:::anim{component="vector-field-2d"}
field: { x: "-y", y: "x" }     # 向量场的两个分量，键固定是 x、y，变量也是 x、y
range: { x: [-3, 3], y: [-3, 3] }
dt: 0.02
particles: 300                 # 粒子数，可省略（默认 200，最多 2000）
sliders: [...]
:::
```

- 滑块名不能叫 `x`、`y`。
- 箭头的方向是场的方向，长短随场的大小变化（以格点上较大的那些为满长，太小的也留三成长度）。
- 改了滑块，粒子接着跑（只是场变了），不重新开始。

Oscillator：一串物块排在两堵墙之间，用弹簧连起来。单个振子、耦合振子、简正模都用它。上面画物块和弹簧，下面画每个物块的位移随时间变化的曲线。

```yaml
:::anim{component="oscillator"}
masses: [1, 1]          # 从左到右每个物块的质量，可以用式子，必须大于 0
springs: [1, k, 1]      # 从左墙到右墙依次 N+1 根弹簧的劲度系数（N 是物块数），写 0 表示那一端不连墙
damping: 0              # 阻尼系数（每个物块受 -damping × 速度 的力），可省略，默认 0
initial: [1, 0]         # 每个物块的初始位移，可以用式子；初速度都是 0
dt: 0.01
sliders: [...]
:::
```

- `springs` 的个数必须比 `masses` 多 1，`initial` 的个数和 `masses` 一样。改了滑块，振子从初始位移重新开始。
- 物块最多 8 个。劲度系数和阻尼不能是负数；式子里用了滑块、算出来不合理（质量不是正数等）时，图上显示原因，振子不动。
- 曲线图显示最近 20 秒（模拟时间），纵轴跟着跑出来的最大位移放大。

**第二批组件的写法**（做一个补一个；没写进这里的组件，内容里先不要用）。式子、`label`、滑块的规矩和第一批一样。

LinearMap2D：线性变换怎样拉扯平面。从单位矩阵慢慢变到目标矩阵，网格、单位正方形、两个基向量的像跟着变（批次 9 时做的，写法你定的）。

```yaml
:::anim{component="linear-map-2d"}
matrix: [[1, k], [0, 1]]      # 目标矩阵，按行写；元素可以写式子、用滑块名
range: { x: [-3, 3], y: [-3, 3] }
show: [grid, square, basis]   # 画哪几样，可省略，默认就是这三样
vectors:                      # 另外画的向量，可省略，最多 6 个
  - x: 1
    y: 1
    label: |
      $\vb v$
sliders: [...]
:::
```

- 几个矩阵依次作用时，用 `steps` 代替 `matrix`：最多 4 步，每步写 `matrix`，可以加一句 `label`，画面下面显示「第几步：说明」。先作用第一个，合起来是后面的矩阵乘在左边，例如 $A=PDP^{-1}$ 依次写 $P^{-1}$、$D$、$P$。`matrix` 和 `steps` 只能写一个。
- 插值是 $(1-s)I+sM$，$s$ 从 0 到 1，两头放慢；分步时第 $k$ 步是 $\bigl((1-s)I+sM_k\bigr)M_{k-1}\cdots M_1$，步与步之间停半秒。$A$ 的实特征向量在整个插值过程中都是特征向量，所以 `eigen` 那两条直线上的点一直留在线上（分步时不是这样）。行列式变号的矩阵，插值途中会经过一个不可逆的时刻，平面被压成一条线。旋转矩阵插值途中不是旋转，图形会先缩小（转 90° 时一半处缩到约 0.71 倍）；讲旋转时请读者比较开头和结尾，说明里交代中途只是从 $I$ 到 $A$ 的过渡（批次 9 写内容时提的）。
- `show` 能写的：`grid` 变换后的网格（原来的网格照常画在下面）；`square` 单位正方形的像，行列式为负时换一种颜色；`circle` 单位圆的像；`basis` 两个基向量的像（正好是矩阵的两列，图例写「e₁ 的像」「e₂ 的像」；颜色取网站主题的绿和橙红，正文按图例名指，不写颜色）；`eigen` 最终矩阵的实特征向量所在的直线（虚线；单位矩阵的倍数时角上写「每个方向都是特征向量」）；`det` 角上显示当前矩阵的行列式，插值途中跟着变。`square`、`circle` 另画一圈虚线表示原来的样子。
- `vectors` 画出原来的向量（淡的虚线）和它的像，图例里写 `label`。
- 1× 时每一步 2 秒（你定的）；放完停在终点，再点「播放」从头重放。「进度」条能拖到任意时刻，拖的时候暂停。改了滑块，画面直接跟着变，不从头放。「重置」回到开头并复原滑块。系统设置了「减少动态效果」时，一开始就停在终点。
- `det`、特征向量的方向会把数显示在图上，和别的图一样，不要正好是简单题、中等题要算的数。
