## 3. 验证

起点为 `cs/c4` 的 `6d7c060`。下列测试使用小程序、独立参考缓存和临时 Markdown，没有向正式内容添加验收示例。

### 缓存

| 验收项 | 检查方法和结果 |
| --- | --- |
| 容量相同，映射不同 | 对 00、04、10、00 逐次断言。4 组直接映射为缺、缺、缺、缺；2 组 2 路为缺、缺、缺、命。2 路的 LRU 和 FIFO 均通过。画廊走到第 4 步，主表 44 周期，对照表 34 周期。[两表同一步](cs-c4/cache-compare.jpg) |
| LRU / FIFO | 1 组 2 路访问 00、08、00、10、00，LRU 为缺、缺、命、缺、命；FIFO 为缺、缺、命、缺、缺。 |
| random | 固定种子 7，访问 00、04、08、00、04、08、00，结果为缺、缺、缺、缺、命、缺、命。三次替换的路号依次为 0、0、1。从第 7 步退回第 2 步、截去未来再重放，路号、种子、缓存内容和计数恢复一致。 |
| 矩阵 | 对 0x80 处的 8 × 8 字节矩阵，分别生成行序、列序地址。4 行直接映射、2 组 2 路、1 组 4 路在 LRU 和 FIFO 下，行序均缺 16 次，列序均缺 64 次。16 行直接映射列序缺 16 次。浏览器也把列序演示走完了 64 步。 |
| 写入策略 | 对 w00、00、w10、04、00 核对每次访问。写回为缺 11、命 1、缺 21、缺 11、缺 21，共 65 周期，写回两次。写直达为缺 10、缺 11、缺 10、缺 11、命 1，共 43 周期，写内存两次。画廊两侧最终计数一致。 |
| 性质 | `core/cache.test.ts` 用 120 个配置各跑 100 次读写。参照模型存全块号，用有序队列选牺牲块。12,000 次访问的命中、所用路、换出块和周期逐次一致。 |

### P8 接缓存

| 验收项 | 检查方法和结果 |
| --- | --- |
| A4、只缓存数据 | 85 条完成，输出 [136]。无缓存 245 周期；4 组直接映射 141 周期，4 缺、12 命。测试取出全部 16 条 LD 的费用，均为 12、2、2、2 循环。浏览器走到停机后图上保留第 22–85 条。[数据缓存与周期图](cs-c4/cpu-cache-chart.jpg) |
| A4、取指也进缓存 | 4 组直接映射和 16 组直接映射都是 486 周期、30 缺、71 命；4 组 2 路为 276 周期、9 缺、92 命。测试分别核对输出和总数。 |
| A2 与微步 | 写回逐条 1、12、1、2、1，共 17。写直达逐条 1、11、1、12、1，共 26。另测数据读在执行、数据写在写回计费，CALL/RET 共用同一栈块，跨 0xFF 的取指访问 0xFF 和 0x00 两块。手改内存保留缓存，出错回看能还原出错前的取指。 |
| 性质 | 90 个随机访存程序 × 25 条指令（含 HLT），配置覆盖两种取指方式、两种写策略和三种替换策略。独立参考缓存按指令的实际地址重走取指和数据访问，2,250 条指令的周期逐条等于 1 加各次费用。 |

### 流水线

| 验收项 | 检查方法和结果 |
| --- | --- |
| ADD 接 ADD | 关闭转发，第二条停 2 拍，第 8 拍写回，第 9 拍 HLT 写回。开启转发，第二条第 6 拍写回，共 7 拍，EX 向 EX 转发。 |
| LD 接 ADD | 开启转发，停 1 拍，第 7 拍写回，共 8 拍，转发源为 MEM；关闭转发，停 2 拍，第 8 拍写回，共 9 拍。测试同时核对重复的 ID、EX 气泡数和箭头的动态指令编号。[LD 后使用](cs-c4/pipeline-load.jpg) |
| 无条件跳转 | 按方案的六行程序单步。两种分支策略都用 10 拍，等待策略停止取指两拍，预测不跳冲掉两条。两者最终 R1 = R2 = 0、R3 = 7。另测错误路径上的 HLT 被冲掉后能从目标恢复取指。 |
| 条件不跳 | 对 LDI、SUB、JZ、LDI、HLT 的五条程序检查总拍数。等待策略 11 拍，预测不跳 9 拍。 |
| 标志依赖 | LDI、SUB、JNZ、NOP、HLT 的预测不跳版本，关闭转发时 SUB、JNZ 各停 2 拍，冲 2 条，共 14 拍；开启时无数据停顿，冲 2 条，共 10 拍。 |
| A1 | 有转发时预测不跳 / 等待分别为 56 / 58 拍，无转发时为 78 / 80 拍。四种均完成 34 条、输出 [55]。预测不跳冲掉 18 条；无转发停 22 拍。浏览器在第 56 拍显示 CPI 1.65。[分支冲刷](cs-c4/pipeline-flush.jpg) |
| 性质与截止 | 160 段可停机的随机程序，每段跑四种设置。640 次排程的完成数、寄存器、标志、内存、输出和停机状态均与顺序 P8 一致。每次用时至少为完成数加 4，同程序开启转发或预测不跳都没有变慢。另测死循环恰在第 1000 拍报告「1000 拍内没有停机」，自修改和错路输入输出都有独立用例。 |

## 4. 我替你定的

- 缓存路号从 0 开始，表格用访问序号表示 LRU / FIFO 的先后。没有组号位或偏移位时显示 ∅。编辑地址流后按「应用地址流」才重置，输入到半截或格式错误时保留当前模拟。
- P8 取指走缓存时，取指微步立即显示费用。若随后因指令非法或输入输出错误停机，恢复该指令取指前的缓存与周期。后退仍能看到取指瞬间。这样同时满足取指当拍可见和出错指令不计费两条约定。
- 单独写 `fetch: through-cache` 或在 `view` 里点名 `cache/chart` 时，编译器要求同时给出缓存配置。缓存和周期图的位置沿用步进条下方的折叠面板。每条指令的柱子可查看指令序号、地址和周期。流水线动态行按取指编号，现时图展示最近 32 拍，历史每页最多 32 拍。CPI 显示两位小数，第一次写回前显示「—」。

## 6. 和方案不一致的地方，以及原因

无范围或验收口径变更。已有 CPU 的可见行为按本级要求调整，内存默认展开，栈第一次非空时展开；没有配置缓存的 CPU 保留原有周期和观测量。流水线按需调用原 P8 内核求取指令结果，错误预测只推进私有状态，寄存器、标志、输出等架构状态在 WB 更新。
