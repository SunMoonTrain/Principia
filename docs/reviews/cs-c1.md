## 重要 1 · 补码加减法看不见进位

- 位置：`packages/sim/src/Bits.tsx:72`–`78` 只画 a、b、结果三行；内核 `packages/sim/src/core/bits.ts:42` 算出了 `carry`，界面没用上。
- 依据：`docs/cs-plan.md`「模拟器清单」里 bits 那一行：「逐位单步加减法，进位一格格往上走，看着溢出那一刻」；「组件怎么动」里 `sub`：「显示 a − b = a + ~b + 1」。
- 现象：`127 + 1` 的第 1 到 7 步，结果行一直是 `00000000`，只有当前位下面那条横线在挪；进位从第 0 位一路传到第 7 位，只写在步骤说明里。这一段正是「亲眼看着溢出」要看的东西。
- 建议：加一行「进位」。处理第 i 位时，进位进标在第 i 列，进位出标在第 i + 1 列；当前列在 a、b、进位、结果四行一起高亮；最高位的进位出单独标出（它就是加法的 CF）。减法在「取反」那一步把 b 行换成 ~b（或者加一行 ~b），第 0 列的进位进标 1。
- 怎么验：`127 + 1` 第 1 到 7 步，进位行每步多一个 1 往左走；第 8 步符号位那一列进位进 1、进位出 0；`5 − 7` 第 1 步出现 `~b = 11111000`，第 0 列进位进为 1。

## 重要 2 · 累加只能从 0 开始，演示不出「大数吃小数」

- 这是方案的疏漏：附录 B 的 `accumulate` 没给起点。实现照方案做了，没有错。
- 现象：从 0 开始、最多加 1000 次，`stuck` 在正常参数下几乎碰不到，只有 `delta` 本身舍成 0、或者和上溢成无穷大时才会出现（我传 `start: 16777216` 试过，参数被忽略，结果是 9）。「加的数不到半个 ULP，被舍掉了」那条说明写好了却演示不出来；而「大数吃小数」正是要看的「精度丢失时怎样跳变」。
- 要补的（`docs/cs-plan.md` 已同步改）：`accumulate` 加参数 `start`，默认 0，可以写字符串，转成单精度后必须是有限数。寄存器从 float32(start) 开始；精确和 = start + k·delta，按十进制精确算（起点也按十进制）；`error`、`stuck` 照旧。`plan.md` 的 float32 写法跟着改。
- 验收（Node 上用 `Math.fround` 核对过）：
  - `start: 16777216, delta: 1, count: 3`：三步都停在 16777216，`stuck` 为 1，说明是「正好半个 ULP，取尾数为偶的原值」（你们补的这条说明正好用上）。
  - `start: 1, delta: "2^-25", count: 3`：三步都停在 1，说明是「加的数不到半个 ULP，被舍掉了」。
  - `start: 16777216, delta: 3, count: 3`：依次是 16777220、16777224、16777228，每步跳 4 而不是 3（每次都正好落在两个数中间，取偶）。
  - 画廊加一个演示，用最后这一组。

## 重要 3 · 计算机组件的 `sliders` 不起作用

- 位置：`packages/sim/src/specs.ts:18`、`:26`、`:37`、`:47` 让三个组件都收 `sliders`；`src/components/AnimRuntime.tsx:10`–`20` 在组件下面画一个 `SimSliders`，可滑块的值只存在 `SimSliders` 自己的状态里，组件拿不到。
- 现象：内容里给 bits 写 `sliders`，构建 0 个错误（实测），页面上出现能拖的滑块，拖了什么都不变。`plan.md`「统一约定」写着「每个组件都有参数滑块和重置」，写内容的人很可能顺手加。
- 建议：三个组件的规格去掉 `sliders`，写了就构建报错，说明计算机组件暂时不收滑块；删掉 `AnimRuntime` 里的 `SimSliders`；`plan.md` 计算机部分写一句。以后哪个组件真要滑块，再把值接进它的参数。

## 小问题

### ① 浮点加法的过程里看不到 b 和对齐后的尾数

- 位置：`packages/sim/src/Float32.tsx:100` 只画寄存器那一行（「装回」之前一直是 a）；`packages/sim/src/core/float32.ts:111` 把精确和写成「N × 2⁻¹⁴⁹」，N 是几十位的整数，读不出东西。
- 建议：第 1 到 5 步同时画 a、b 两行；「对齐」那一步加一行对齐后的尾数，把保护位、舍入位、粘滞位标出来；精确和用以结果阶码为准的二进制写（多出来的低位另色），右边的「精确和」十进制照留。

### ② 画廊里的计算机演示不经过参数规格

- 位置：`packages/sim/src/GalleryDemo.tsx:8`–`18` 的参数直接交给组件。原有动画的演示由编译器测试逐个检查能不能通过构建（`plan.md`「可复用动画组件库」），计算机的没有。
- 建议：加一条测试，每个演示的参数都用 `SIM_SPECS[组件名].schema` 解析一遍，并用解析后的结果渲染（和小节里走同一条路）。

### ③ 不可见字符显示成空的

- 位置：`packages/sim/src/TextEncoding.tsx:14` 用 `character.trim() || '空白'`：空白字符会显示「空白」，零宽连接符 U+200D 这类格式字符不算空白，那一行的标题就是空的（实测 `é👩‍💻` 的第 3 行）。
- 建议：格式字符（`/\p{Cf}/u`）和控制字符显示成「不可见」或它的名字，例如「零宽连接符」。
